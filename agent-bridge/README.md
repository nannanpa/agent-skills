# 智能体通讯桥（agent-bridge）

零常驻的 agent 间消息桥：一个纯标准库 Python 脚本＋一个共享目录，即可让多个 agent 互递任务与回执。无 .app、无常驻进程、无宿主注入；由人或定时任务拉起，查收件箱、按线程限三领信、把信全文打到 stdout。

## 能做什么

- 在**同一台机器**上让任意多个 agent 互递消息：每个 agent 是一个**端点**，名字自己起。
- 停函收口：回执即终／协商限三／超限与缺字段信进 `pending-人工/` 由人裁决。
- 收件箱可配置：默认 `./.bridge`（init 时求值成绝对路径记入本机 identity），`--ws <目录>` 随时覆盖。

## 用法（只有两条命令）

```bash
python3 bridge.py init          # 首次配置：本端叫什么、对端叫什么、收件箱放哪（回车即用默认）
python3 bridge.py <端点名>       # 收自己名下的信；无信静默 exit 0
```

- 首次 `init` 会给出候选名（取自本机 hostname 清洗，如 `mac-mini-a`），直接回车即用；同一台机器上第二个 agent 再跑一次 `init` 即可。
- 发信＝把信写进**收端**的目录 `<收件箱>/<收端端点名>/`；文件名 `<发端>-YYYY-MM-DD-<主题>.md`（或 `.txt`），主题限小写字母数字连字符。样例见 `sample-letter.md`（样例本身不能直接投递，须按命名式改名、一文件一信）。
- 收信＝人工或定时跑 `python3 bridge.py <本端端点名>`，stdout 返回一行 JSON（含信全文）。文件名不合式的文件不领、不报错，只在 stderr 报一行"未领 N 个不合式文件"。
- 收件箱临时换目录加 `--ws <目录>`；收件箱目录建议写进 `.gitignore`（init 只提示，不自动改）。

## 从 1.0.x 迁移（wb／dsh 用户）

v1.1.0 有两条**破坏性变更**：①命令面从 `bridge.py wb|dsh` 改为 `init` ＋ `bridge.py <端点名>`；②stdout JSON 的 `from`／`to` 从 `"WB"/"DSH"` 改为端点名。迁移三步：

1. `python3 bridge.py init`，把原来的两端登记成端点（名字仍可叫 `wb`、`dsh`）。
2. 若端点用了新名字，加别名让旧命令继续可用：`python3 bridge.py init --alias wb=<本端> --alias dsh=<对端>`（已 init 过则手工编辑 `<收件箱>/bridge-endpoints.json` 的 `aliases`，这是别名唯一入口）。
3. 旧根目录平铺的信：收信时加 `--legacy-scan` 扫一遍；依赖旧 JSON 大写 `from` 的消费方加 `--legacy-from`（均只保留一个版本，CHANGELOG 详见下）。

v1.1.0 起不再支持 `AGENT_BRIDGE_WS` 环境变量——收件箱由 init 记录＋`--ws` 覆盖取代。

## 边界与已知限制

- 只传消息不交会话；敏感内容不落盘。
- 当前不接宿主 hook，脚本不会被自动拉起；自动收信靠定时任务扫箱。
- 跨机（ws 代号、端点对→ws 路由、云盘占位）属跨机扩展层，本版不含；协议信头字段升级属协议 v1.2 另件。
- 无 `--only` 单封过滤；无重试与超时；并发互斥依赖 fcntl，Windows 等无 fcntl 环境降级为无锁运行（会提示，勿并发跑两个实例）。
