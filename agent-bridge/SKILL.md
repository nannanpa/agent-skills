# agent-bridge · 智能体通讯桥（脚本 v0.1.3 · 发布版 1.0.1）

## 定位（钉死，不漂移）

**零常驻的智能体通讯桥，技术形态＝共享目录文件通道；当前形态＝B 档「人工投递查看器」**——实体是一个 Python 脚本（`bridge.py`，约 170 行，纯标准库）＋共享收件箱目录，由人或定时自动化手动拉起，查收件箱、按〔线程〕限三领信、把信全文打到 stdout；**不做宿主注入，不假设任何 Stop hook**。

本包只做 B 档。A 档（对端自动唤醒、事件驱动投递）需要额外组件，**不在本包内、本包不承诺**；C 档（无文件读写能力）走人工复制粘贴，也用不上本桥。

## 何时用

- 给另一个 agent 递审查请求或任务，不想手工复制粘贴。
- 线程要收口：按停函协议（回执即终/协商限三/第 4 封硬拦）。
- 新 agent 接入：判定它属于哪一档——能挂 hook 的（A 档，需另配组件）、能读写文件的（B 档，用本桥）、只能人肉转述的（C 档，人工复制）。

## 用法

1. **确认收件箱**：默认 `~/Documents/deepseek-harness/default-workspace`。换机/换用户时用 `--ws <目录>` 指定，或设环境变量 `AGENT_BRIDGE_WS`：
   ```bash
   python3 bridge.py dsh --ws /path/to/inbox
   AGENT_BRIDGE_WS=/path/to/inbox python3 bridge.py dsh
   ```
   两个都不给才用默认值。目录不存在＝exit 2 并提示怎么改。
2. **发信**＝往收件箱写一封符合四段式格式的 md/txt（格式见「边界」节，完整样例见 `sample-letter.md`）。
3. **收信**＝人工/定时跑 `python3 bridge.py dsh`（本端用 `wb`）。当前无宿主 hook，脚本不会被自动拉起。
4. **处理前按文件名单封 claim**：只把本次要处理的那封移入 `claimed/`，不要裸跑批量领信——收件箱若有其他旧信，裸跑会把它们一并领走或转 `pending-人工/`。单封命令：
   ```bash
   mv wb-prompt-YYYY-MM-DD-<主题>.txt \
      claimed/$(date +%H%M%S)-wb-prompt-YYYY-MM-DD-<主题>.txt
   ```
   判据：回执落盘时 `claimed/` 有本线程记录、原信不在根目录。
   **手工 claim 与限三计数**：脚本靠扫 `claimed/` 里同〔线程〕的信件数来算"第几封"，所以手工移进去的信**同样计入**。含义——手工搬一封就等于消耗一次配额；想让限三有意义，就别把不该算的信手工塞进 `claimed/`。
5. **硬拦排查**：`pending-人工/` 里的信＝协议闸门拦下（第 4 封超限、第 3 封派发、缺线程/缺类型、请示路由、终结后新信），由人裁决后人工转投或废弃。

## 边界

- 只传消息不交会话；敏感内容不落盘。
- **退出码分层**：参数／环境级错误（无 side、side 非法、`--side` 缺值、收件箱不存在／不可读）＝中文报错＋怎么办＋**exit 2**；协议闸门与运行时状态（无信、并发让路、被领走、缺线程/类型、请示、超限）＝**静默 exit 0**，绝不打断 agent 正常一轮。
- **消息协议（自含，规则全部写在这里，不依赖任何外部文档）**：发信为 md/txt，首两行必填 `〔线程〕<slug>`、`〔类型〕<派发|回执|终结|请示>`，其后四段：
  - 〔任务〕一句话
  - 〔结论/判据〕要点＋完整绝对路径（缺依据写「未核实＋依据」）
  - 〔边界〕只读哪些、不改哪些、不代哪些决策
  - 〔回执〕落点名＋是否需回函

  全文 ≤10 行（**由发信方自觉**：脚本只校验〔线程〕〔类型〕信头与类型枚举，不数行数、不查四段是否齐全）。停函规则：回执即终、同线程含回执最多三封、第 3 封不得为派发、第 4 封转 `pending-人工/`、人工「本轮终结」优先于机器规则。文件名约定 `wb-prompt-*.txt`（A 端→B 端）／`dsh-*函-*.md`（B 端→A 端），桥按此分流；文件名只是分流约定，可换成你自己的两侧前缀，改脚本里的 pattern 即可。**投递注意：一个文件＝一封信**；对照样例见 `sample-letter.md`（该文件是样例不是信，直接投递脚本会静默找不到——文件名不合 pattern 不报错）。
- **不提供**：`--only` 单封过滤、多目录并行、事件监听、自动投递。这些不在当前版本，需要请自行扩展或走版本升级。

## 常见问题

**什么情况不用？**

- **只有一个 agent 在干活**：没有第二方，桥空转。
- **消息涉密／未定稿／不许落盘**：桥是文件通道，落盘即留痕；这类走当面或口头。
- **线程已终结**：`claimed/` 里已有同线程回执，再发只会进 `pending-人工/`。要重启就换新线程名，别在原线程续。

**出错怎么办？**

- 看到 `[bridge] … 怎么办：…` ＋ **exit 2** ＝参数或环境错，**不是"没信"**。按提示改参数／路径，别原样重试。
- 换机后立刻报"收件箱目录不存在"：加 `--ws <你的目录>` 或设 `AGENT_BRIDGE_WS`。
- `pending-人工/` 里三类，各判各的：①缺〔线程〕或〔类型〕＝信头不合格，补齐重投；②第 3 封派发、第 4 封＝协商已到上限，人工裁决（终结，或开新线程）；③请示＝路由错了，桥只送本端负责人。
- Windows 上跑：脚本会提示"无 fcntl，已降级为无锁运行"——功能可用，但**别并发跑两个实例**，否则可能重复领同一封信。

**怎么提前收束／退出？**

- **回执即终**：任一方发〔类型〕回执，线程关闭，后续信自动转人工。
- **协商限三**：同线程最多三封（含回执），第四封硬拦。
- **人工「本轮终结」优先于机器规则**：负责人说停就停，机器不得续传。

## 多场景示例

### 场景 A · 向对端递审查（示例线程 `review-001`）

```bash
# 1) 落信：收件箱写 wb-prompt-2026-11-18-review-001.txt（内容照 sample-letter.md）
# 2) 对端收信
$ python3 bridge.py dsh --ws /path/to/inbox
{"file": "wb-prompt-2026-11-18-review-001.txt", "thread": "review-001",
 "n": 1, "from": "WB", "body": "〔线程〕review-001\n〔类型〕派发\n…"}
# 3) 对端回函落在同一收件箱根目录，本端用 `python3 bridge.py wb --ws ...` 领
```

### 场景 B · 向定时型 agent 派活（示例线程 `task-001`）

```bash
# 对端没有脚本，靠定时任务/人工唤起——那就在它的定时任务里跑同一个 bridge.py：
$ python3 bridge.py wb --ws /path/to/inbox
# 只要收件箱路径一致、文件名前缀对得上，桥就能领到信；不需要额外的 done/outbox 目录。
```

### 场景 C · 跨机（共享同步目录，可选）

```bash
# 收件箱指向两端都挂载的同步目录（iCloud/Dropbox/局域网盘皆可）
$ AGENT_BRIDGE_WS="$HOME/Library/Mobile Documents/com~apple~CloudDocs/bridge" \
  python3 bridge.py wb
# 协议四段与闸门一字不改，差异只在传输层；注意同步延迟会造成"以为没信"。
```
