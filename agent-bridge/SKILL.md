# agent-bridge · 智能体通讯桥（脚本 v0.2.0 · 发布版 1.1.0）

## 定位（钉死，不漂移）

**零常驻的智能体通讯桥，技术形态＝共享目录文件通道；当前形态＝「人工投递查看器」**——实体是一个 Python 脚本（`bridge.py`，475 行，纯标准库）＋一个共享收件箱目录，由人或定时自动化手动拉起，查收件箱、按〔线程〕限三领信、把信全文打到 stdout；**不做宿主注入，不假设任何 Stop hook**。同一台机器上任意多个 agent 各为一个**端点**，各扫各的信箱子目录，互不串线。

本包只做单机主路径。跨机（ws 代号、端点对→ws 路由、云盘占位）属跨机扩展层，**不在本包内、不承诺**；C 档（无文件读写能力）走人工复制粘贴，也用不上本桥。

## 何时用

- 给另一个 agent 递审查请求或任务，不想手工复制粘贴。
- 线程要收口：按停函协议（回执即终/协商限三/第 4 封硬拦）。
- 新 agent 接入：判定它属于哪一档——能挂 hook 的（A 档，需另配组件）、能读写文件的（本桥）、只能人肉转述的（C 档，人工复制）。

## 用法

1. **确认收件箱**：默认 `./.bridge`，init 时求值成绝对路径写进本机 identity，此后从任何 cwd 调用都读这条记录；临时换目录用 `--ws <路径>`：
   ```bash
   python3 bridge.py <端点名> --ws /path/to/inbox
   ```
2. **首次配置**（只此一次，问三句、回车即用候选名）：
   ```bash
   python3 bridge.py init
   ```
   落盘两处：`<收件箱>/bridge-endpoints.json`（端点注册表，只增不改）＋`~/.agent-bridge/<端点名>.identity`（本机身份，不同步）。对端也要各自 init 一次。
3. **发信**＝往收件箱里**收端**的子目录写一封符合四段式格式的 md/txt，文件名 `<发端>-YYYY-MM-DD-<主题>.md`（主题限 `[a-z0-9-]`；格式见「边界」节，完整样例见 `sample-letter.md`）。
4. **收信**＝人工/定时跑 `python3 bridge.py <本端端点名>`（一轮只投一封）。当前无宿主 hook，脚本不会被自动拉起。
5. **处理前按文件名单封 claim**：只把本次要处理的那封移入 `claimed/`，不要裸跑批量领信。判据：回执落盘时 `claimed/` 有本线程记录、原信不在收端子目录。**手工 claim 与限三计数**：手工移进去的信同样计入。
6. **硬拦排查**：`pending-人工/` 里的信＝协议闸门拦下（第 4 封超限、第 3 封派发、缺线程/缺类型、请示路由、终结后新信），由人裁决后人工转投或废弃。

## 边界

- 只传消息不交会话；敏感内容不落盘。
- **退出码分层**：参数／环境级错误（未 init、端点未登记、收件箱不可读）＝中文报错＋怎么办＋**exit 2**；协议闸门与运行时状态（无信、并发让路、被领走、超限转人工）＝**静默或 stderr 一行＋exit 0**，绝不打断 agent 正常一轮。
- **消息协议（自含，规则全部写在这里，不依赖任何外部文档）**：发信为 md/txt，首两行必填 `〔线程〕<slug>`、`〔类型〕<派发|回执|终结|请示>`，其后四段：
  - 〔任务〕一句话
  - 〔结论/判据〕要点＋完整绝对路径（缺依据写「未核实＋依据」）
  - 〔边界〕只读哪些、不改哪些、不代哪些决策
  - 〔回执〕落点名＋是否需回函

  全文 ≤10 行（**由发信方自觉**：脚本只校验〔线程〕〔类型〕信头与类型枚举，不数行数、不查四段是否齐全）。停函规则：回执即终、同线程含回执最多三封（按端点对计，同对正反两向合计）、第 3 封不得为派发、第 4 封转 `pending-人工/`、人工「本轮终结」优先于机器规则。
- **不提供**：`--only` 单封过滤、多收件箱并行、事件监听、自动投递。这些不在当前版本，需要请自行扩展或走版本升级。

## 出错怎么办（异常处理）

- `[bridge] … 怎么办：…` ＋ **exit 2** ＝参数或环境错，**不是"没信"**。按提示改参数／路径，别原样重试。
- 换机/换目录后报"还没绑定"或"收件箱缺本端目录"：跑 `bridge.py init` 重新登记，或 `init --force` 改绑；目录被移动过也会给同款提示。
- `bridge.py <名字>` 报"端点未登记"：名字打错或该端点没 init 过；提示里会列出全部已登记端点。
- 投了信但收不到：先查**信落在谁的子目录**（必须进收端那一格，不是 ws 根）；再查文件名是否合 `<发端>-YYYY-MM-DD-<主题>.md|txt`——不合式不领，stderr 会报"未领 N 个不合式文件"，照提示改名重投。
- Windows 上跑：脚本会提示"无 fcntl，已降级为无锁运行"——功能可用，但**别并发跑两个实例**。

## 常见问题

**什么情况不用？**

- **只有一个 agent 在干活**：没有第二方，桥空转。
- **消息涉密／未定稿／不许落盘**：桥是文件通道，落盘即留痕；这类走当面或口头。
- **线程已终结**：`claimed/` 里已有同线程回执，再发只会进 `pending-人工/`。要重启就换新线程名，别在原线程续。

**`claimed/` 里的文件名怎么多了一段？**

- 形如 `<HHMMSS>__to__<收端>__<原文件名>`。`claimed/` 是全收件箱唯一的领信记录目录，信从各端点子目录搬进去后，靠这段标签复原"这对端点收了几封"——限三按端点对计数靠它。别手工改这段。

**两个 agent 能共用一个收件箱吗？**

- 能，而且应该：同一 `<收件箱>` 下每人一格子目录，注册表同表、`claimed/` 一份。**不能共用的是同一格子目录**——投错格等于投给错的人。

**怎么提前收束／退出？**

- **回执即终**：任一方发〔类型〕回执，线程关闭，后续信自动转人工。
- **协商限三**：同线程同端点对最多三封（含回执），第四封硬拦。
- **人工「本轮终结」优先于机器规则**：负责人说停就停，机器不得续传。

## 多场景示例

### 场景 A · 向对端递审查（本端 alice、对端 bob，示例线程 `review-001`）

```bash
# 1) 落信：写进 <收件箱>/bob/alice-2026-11-27-review-001.md（内容照 sample-letter.md）
# 2) bob 收信
$ python3 bridge.py bob
{"file": "alice-2026-11-27-review-001.md", "thread": "review-001",
 "n": 1, "from": "alice", "to": "bob", "body": "〔线程〕review-001\n〔类型〕派发\n…"}
# 3) bob 回函写进 <收件箱>/alice/，alice 用 `python3 bridge.py alice` 领
```

### 场景 B · 向定时型 agent 派活

```bash
# 对端没有脚本习惯，靠定时任务/人工唤起——在它的定时任务里跑同一个 bridge.py：
$ python3 bridge.py bob
# 只要收件箱路径一致、文件落在 bob 名下，桥就能领到信；不需要额外的 done/outbox 目录。
```

### 场景 C · 第二个 agent 加入同一台机器

```bash
# 已有 alice/bob 在跑，第三个 agent carol 接入：各自再 init 一次即可
$ python3 bridge.py init        # 候选自动轮到下一个未占用的字母后缀，回车即用
# 注册表只增不改；carol 收信扫 <收件箱>/carol/，与前两端互不干扰
```

### 场景 D · 跨机（共享同步目录，可选）

```bash
# 两端各自 init 后把收件箱都指到同步目录里的同一 ws：
$ python3 bridge.py alice --ws "$HOME/Library/Mobile Documents/com~apple~CloudDocs/bridge"
# 协议四段与闸门一字不改，差异只在传输层；注意同步延迟会造成"以为没信"。
```
