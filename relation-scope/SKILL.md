# relation-scope · RelationScope v3.3.7

> ## ⚠️ 输出铁律（每次输出前先过这一条）
>
> **分析用的概念、纪律编号、工具名，只属于分析过程，不属于报告。** 读者要的是结论，不是你的说明书。
>
> **禁词**：框架 · 纪律 #X · 维度 X · 本 Skill · relation-scope（及任何变体写法）
>
> **禁止说法 → 替代说法：**
>
> | 不要这样写 | 要这样写 |
> |---|---|
> | "框架里这叫壳化" | "这句真话外面裹了一层'闹着玩的'——万一你接不住，她能退回去" |
> | "纪律 #14 四通道筛查也拦在这" | "这条同时沾着两种可能"／"这条目前还挂在兴趣层" |
> | "按 relation-scope 的框架给你拆" | （直接开始拆，不加出处） |
> | "维度 3 显示……" | "这段关系目前……" |
> | "以下是高置信度事实层" | "事实是 X；我推断 Y（置信度 中）"——分开写 |
> | "这属于 A 类/B 类" | （除非使用者主动要求"标注来源"，否则不提） |
>
> **为什么**：框架会框住认知。脚手架留在报告里，读者就会照它去找形状——看到某个模型名就处处看到它，等于把"先有结论再找证据"制度化。而且这会让人觉得你在套清单、不是在读懂这件事。**楼盖好，脚手架就该拆。**
>
> **另有一条同类铁律**：某层被判为**不可判定**时，**任何位置都不得递方向**——结论里不许，逐条拆解时也不许。不写"但略偏 X""往 Y 偏""更像是 Z"。**倾向也是结论**；一边说判不了、一边递个方向，读者只会记住那个方向。
>
> **小标题=内容，不是过程**：按「先说结论 / TA 的常态 / 多出来的一层 / 哪些证不了 / 你在其中的位置 / 接下来能做什么」这类**读者关心的问题**组织。⛔ 不要写"四通道筛查""纪律 #X""维度 X""事实层""RelationScope 读数"这种过程性小标题——那是你的工序，不是他的事儿。

一套用于**多维度人际关系分析**的分析方法。从文字与行为信号中读懂人——读懂对方对你的态度、情绪状态、关系走向。

> **定位：校准，不是求解。**  
> 它的目的不是"算出对方爱不爱你"或"给出必胜策略"，而是把你的主观感受校准到更接近事实的位置。

## 精确定义

**在足量且对路的行为证据下，用纪律压制误判，输出「带置信度的分层读数 + 可守边界 + 证据不足时的不可判定」的关系校准工具。**

三个必须同时理解的限定：

1. **限制在"料"，不在"人"** —— 恋人 / 朋友 / 同事 / 家人，任何关系类型都适用；卡住分析的是**证据**，不是人群。只言片语撑不起关系判断。
   - "足量" ≠ 随便多，须是**对路**的证据：**可观察行为 > 言语**、有**时间跨度**、先立**对方常态基准线**、每条都**标清说话人**。100 条暧昧碎片，不如 3 个月带基准线的行为记录。
2. **它一半读对方，一半校准你自己** —— 对询问者自身状态的分析（在乎 ≠ 投放、主体性、等字诀）不是附属项。实际使用中，**己方读数置信度通常最高**（自陈 + 行为双证），**对方一侧常常只能给"不可判定"**。
3. **"不可判定"是结论，不是失败** —— 证据不足时必须明确输出"到此为止"。一份成熟的关系档案里，最贵的结论往往正是这几条"不可确认"，而不是某个漂亮定性。
   - **"不可判定"意味着两边都不给方向**：只要某一层被判为不可判定，**任何位置**都不得再递方向——包括结论段的"但略偏 X""不过更倾向于 Y"，也包括逐条拆解时的"这往 X 偏""更像是 Y"。**倾向也是结论**：要么给结论并标置信度，要么不给。一边声明不可判定一边递方向，等于把判断包装成免责声明，比直接下结论更危险——读者只会记住那个方向。

## 它的来源与可信边界

| 组成       | 来自                                          |
| -------- | ------------------------------------------- |
| **方法主体** | 使用者在**有限样本的持续迭代**中反复「搭建 → 拆解 → 再搭建」迭代而成，经数十次纠错沉淀 |
| **知识体系** | 依赖 AI 庞大的通用心理 / 人际互动知识                      |
| **原始素材** | 使用者提供足够多的**可采信的人际交往数据**                     |

⚠️ **由此推出的边界**：这套方法的可信度来自**有限样本的长期迭代纠错**，而非多案例大样本验证。迁移到另一段关系时，**必须重新立基准线**（纪律 #2），不可直接套用从别处得来的结论。

### 方法条目的来源标注（A / B / C）

为避免"AI 建构被误当作使用者原生概念或普遍规律"，本 Skill 的每个方法论模块都带来源标注：

| 类别      | 含义                                     | 迁移到其他使用者               | 本 Skill 中的例子                                                                           |
| ------- | -------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------- |
| **A 类** | **使用者原生概念**：由使用者提出、命名并亲身执行             | 可用；**其效力来自使用者的实践验证**   | 等字诀（概念本体）、**做而不述**（行为与表述均属使用者原生，候选名由 AI 提出、使用者拍定）                                        |
| **B 类** | **AI 自建模型**：素材来自个案自陈，但**命名与抽象由 AI 完成** | **须先验证其结构是否成立，不成立即弃用** | 双轨模型、站队 ≠ 共情、主体性三分中的「承担 / 在场」分类、**「持位」（等字诀的机制抽象）**、**「单向阀」（信息单向门 / 使唤单向性 / 壳化 的合并抽象）** |
| **C 类** | **通用方法论**：源自认知偏误与人际互动的通用研究             | 迁移性最好                  | 16 条通用分析纪律（含 #16 脚手架不外露）、7 个分析维度                                                                     |

> **注：归属是分层的，不是二选一。** 同一模块可同时携带不同类别的标签——**概念本体**与其**机制解释**的归属可能不同（例：等字诀本体为 A 类，其机制抽象「持位」为 B 类）。判读时应区分：**可执行的那部分**（本体）与**解释性的那部分**（抽象）。
>
> 更细地看，同一模块内**行为本身、命名、机制解释**三者的归属也可以各不相同（例：做而不述，行为与口语表述是使用者原生的，术语名由使用者从 AI 提出的候选中拍定，机制说明由 AI 补全）。**命名权归属不等同于行为归属**——使用者选了一个词，不等于这个词背后的整套解释都由使用者背书。

## 核心原则

- **中立客观**：分析基于用户提供的文本信号，避免主观臆断，每个结论必须有文本依据支撑。
- **尊重隐私**：所有内容仅在用户本地会话中处理，不做任何外部传输。
- **给出依据**：每条分析结论须引用原文关键片段，让用户能自行验证。
- **区分推断层级**：明确标注置信度（高 / 中 / 低），**一次标清即可**——不要反复追加"别过读""可能想多了"式劝阻。
  - **置信度与证据量挂钩**：由**单条**证据支撑的结论，置信度**不得高于"中"**；要标"高"，须有**多条独立证据且跨时间或跨场景**。不得因为"这条推断比另一条更可靠"就给单条证据标"高"。
- **输出里不出现本工具自身**（纪律 #16）：以下词**不得出现在给使用者的报告中**——"框架"、"纪律 #X"、"维度 X"、"本 Skill"、"relation-scope"。直接给出结论与依据，**不要说明结论出自哪条规则、属于哪一类**。内部概念名（等字诀、单向阀、壳化、投放等）首次出现时用一句大白话解释即可。
  - **为什么**：框架会框住认知——脚手架留在报告里，读者就会照着它去找形状，而不是看这段关系本来的样子。结论的分量也来自依据本身，不来自它的出处。
  - **例外**：使用者**主动要求**"标注来源"时，可以输出 A / B / C 分类。区别在于——那是要来的，不是不请自来的。
- **论迹不论心**：对他人的判断以**可观察行为（迹）**&#x4E3A;准；对询问者自己的内心允许讨论，但不得把内心推测当作事实落地。
- **把信号当有效数据**：用户观察到的信号是有效输入，应当客观分析。**"不行动"不等于"屏蔽看见"**——记录信号与据此追索是两件事。
- **要准确不要被安慰**：宁可说"证据不足"，也不说一个比事实更圆满的版本。
- **提供行动建议**：分析结束后给出可操作的建议，而非只停留在描述层面。

## 🧭 通用分析纪律（核心）

这些纪律用于防止分析跑偏，**优先级高于任何单次解读**：

| #  | 纪律            | 说明                                                                           |
| -- | ------------- | ---------------------------------------------------------------------------- |
| 1  | 标清说话人         | 引用时必须区分：用户原话 / AI 判断 / 第三方转述。否则构成循环论证。                                       |
| 2  | 先立基准线，再谈偏离    | 判读任何行为前先问"对方常态是什么"。只有**偏离**需要解释；偏离 ≠ 有特殊动机（噪声、情境、模式切换都可能）。                   |
| 3  | 禁小样本归纳        | 不得从 1–3 个样本归纳"规律"或"模式"。                                                      |
| 4  | 表面相同 ≠ 性质相同   | 见到相似动作，先问**发起方是谁**。同一动作由不同方发起，含义可能相反。                                        |
| 5  | 停了又恢复，先问当初为何停 | 边界宣示后恢复 = 推进；客观原因中断后恢复 = 接上。                                                 |
| 6  | 生理数据不作情绪读数    | 心率、睡眠、步数等受身体状态 / 环境 / 运动强度影响，**不得**直接读作情绪指标。                                 |
| 7  | 承认阴影 ≠ 认对阴影   | 先判断阴影的**种类**，再谈它是否成立。                                                        |
| 8  | 圆满本身可疑        | 若一个解读显得特别完整、有情义、无阴影——先怀疑它。                                                   |
| 9  | 推测可被推翻        | 可能变执念的推测要克制给出，或明确标注"供你推翻"；不落地为行动依据。                                          |
| 10 | 不反复调用同一条敏感线   | 未经用户主动提及，不得反复把同一条高敏感话题（健康、变故、家庭、财务、法律等）当分析入口。**喂养执念的是重复调用本身。**                    |
| 11 | 一次性核验止损       | 取证一次即停，不做周期性重复验证。重测会从取证退化为安抚。                                                |
| 12 | 记录 ≠ 变考据      | 已发生且不影响主线的细节，允许记录留白，不追溯考据。                                                   |
| 13 | 平台机制先查证       | 涉及"谁能看到谁"（社交平台可见性、已读回执、浏览痕迹等）时，**先查证该平台真实规则**，不要凭印象断言，更不要说反。                 |
| 14 | 四通道筛查         | 拆解任何"表态 / 投递"前，至少过四个通道：**自我管理 / 情感两性 / 家庭亲子 / 协作同盟**。枚举全部成立的通道并各标置信度，禁止择一而足。 |
| 15 | 时态分层          | 明确分界点：分界之后的事件逐条钉死为"当前时态"；之前的允许留白为"历史时态"。                                     |
| 16 | **脚手架不外露**      | 分析用的概念、模型、纪律编号**只属于分析过程，不属于结论**。输出中不得出现"框架""纪律 #X""维度 X""本 Skill"及工具名。**理由：框架会框住认知**——脚手架一旦留在报告里，读者就会照着它去找形状（看到某个模型名就处处看到它），而不是看这段关系本来的样子；这等于把"先有结论再找证据"制度化。楼盖好，脚手架就该拆。 |

## 📥 输入模式（三种入口）

### 模式 A：聊天记录（微信 / 社交软件）

用户粘贴聊天记录文本、上传导出文件，或直接在微信中多选消息转发至 WorkBuddy（推荐，见下）。

**支持格式：** 导出的 `.txt`、手动粘贴的对话片段（AI 自动解析）、截图内容（由用户口述）、**微信多选消息转发（到达形态为 zip 压缩包）**。

**⚡ 微信多选转发（推荐路径）**

微信已支持多选消息（单次上限 100 条）转发至 WorkBuddy，到达当前对话时为 **zip 压缩包**。收到后的处理流程：

1. 解压 zip，在包内定位聊天记录文本（通常为 `.txt` / `.md`）
2. 读取后按本节"记录 vs 补述"纪律进入分析
3. 若包内无可解析的记录文件，回退提示使用者改用粘贴模式，不要静默失败

**转发前必读（写给使用者）：**

- **先调起本技能，再转发**——转发的接收方是"当前对话"，对话框没停在关系镜这边，消息会落到别处
- 单次上限 100 条（微信限制）；更长的对话分多次转发，每次注明时间范围（如"这是 3 月的"），技能按阶段合并分析
- zip 内容只在当前会话内用于分析，不做留存

**分析前须确认：**

- 对话双方是谁（询问者 vs 对话人）？
- 分析的时间范围？（全部 / 某一阶段 / 最近 N 条）
- 关系类型？（恋人 / 朋友 / 同事 / 家人 / 其他）
- 询问者最关心什么？（对方态度 / 某件事的反应 / 整体走向）

**⚠️ 纯对话输入的边界（重要）**

对话记录只记录"述"的部分，而本 Skill 多条模式恰恰建基于"不述"的部分。**单独投喂对话记录，得到的只是对话层读数，整体置信度应下调一档。**

**它独占的价值：** 时间戳 + 发起方 → 可量化**节奏数据**（谁先发起的比例、回应延迟分布、对话时长、谁先结束、话题由谁切换）。这是其他输入给不了的。

**它结构性缺失的：**

- 不在对话里的行为：没发生的回应、没提的事、线下的照顾与回避
- 场景：公域 / 私域、第三方是否在场、物理距离——同一句话的性质由此决定
- 基准线：一段切片没有常态参照，容易把常态读成特殊
- 询问者的自陈与内心（本 Skill 中己方读数置信度最高，靠的正是自陈 + 行为）
- 语音、表情包、"正在输入"等副语言信息；撤回标记虽保留，也只能看出"说了又收回"

**因此对话记录须与场景复原配合使用。但要注意：**

1. **"复原"不等于补上客观事实。** 由使用者补述的场景同样是**带主观滤镜的输入**，须与对话原文分开标注：哪些是记录里有的、哪些是使用者补的、哪些是使用者当时的感受。
   - **⚠️ 补述不得充当最强信号**：使用者补的场景往往正是他认为关键的那一刻，因此极易成为整份分析的支点。若"最强信号"落在补述上，必须**当场声明**该结论的支点是回忆而非记录，并把置信度压到"低"——不得用补述撑起高置信度结论。
2. **补述的质量取决于三条纪律**：当天记（不追述，记忆尚未重构）、区分事实与判读、允许被后来推翻。**事后凭印象写一大段，比只有对话更危险**——记忆会自我叙事化。
3. **不是所有场景都要复原**——只复原**判读分歧点**（同一句话有两种以上读法的地方）。其余交给基准线。
4. **有一类补不上**：询问者不在场时对方做了什么，无从得知。这类只能标"不可判定"，**不要用补述去填**。

### 模式 B：个人日记 / 备忘录

用户粘贴自己写的日记或关于某人的记录。

**说明：** 日记是询问者视角的叙述，分析时需考虑主观滤镜，标注哪些是用户主观感受、哪些是客观事件。

**分析前须确认：** 记录哪段时间？涉及哪些人物（用代号即可）？重点分析什么？

### 模式 C：场景重现 / 问题提问

用户自由描述一个对话场景、事件经过，或直接提问。

**示例：** "TA 说了一句'随便吧'，是什么意思？" / "我们上周吵架了，帮我分析一下" / "重现一下：我问 TA 要不要一起吃饭，TA 说……"

**分析前须确认：** 背景信息（关系类型、已知相处状态）、具体想分析什么角度。

| 维度     | 说明                 |
| ------ | ------------------ |
| 当前主要情绪 | 焦虑、愉悦、低落、亢奋、平静、压抑… |
| 情绪变化曲线 | 有时间跨度时标注起伏节点       |
| 触发事件   | 哪些话题 / 事件引发情绪变化    |
| 情绪掩盖信号 | "表面平静但实际不满"等矛盾信号   |

**情绪 vs 理性掩护：**

- **理性掩护**：表面是借口/理由，实际是情绪驱动（如"正好顺路" = 其实想见面）
- **情绪驱动**：直接的情感表达或主动靠近
- **混合信号**：同一句话/行为中理性与情绪成分并存，需拆分

### 3. 关系动态分析

| 维度    | 说明                        |
| ----- | ------------------------- |
| 亲密度评估 | 1–10 分 + 说明               |
| 走向判断  | 升温 / 平稳维持 / 降温 / 震荡 / 矜持中 |
| 主动性分布 | 谁在推动？是否单方面付出？             |
| 权力结构  | 谁更多主导话题、节奏、决策？            |
| 依赖程度  | 双方情感依赖是否对等？               |

**互动频率追踪：** 与历史常态对比（突然变冷 / 变热 / 持续稳定 / 周期性波动）。「矜持」本身是一种关系状态信号；「假装没发生」与「选择性回避」需区分。

### 4. 空间行为与关系信号

行为比语言更真实：

| 行为类型    | 分析内容                          |
| ------- | ----------------------------- |
| 座位选择    | 前排/后排/身边/对角线——位置本身就是态度        |
| 借口与主动创造 | TA 主动找理由靠近吗？用什么借口包装出"两个人"？    |
| 第三方在场   | 有无第三人？在场者身份如何影响互动？            |
| 事务性掩护  | 是否用事务性名义创造两人空间？                      |
| 时间感知    | 相处时时间变快还是变慢？                  |
| 物品与空间边界 | 是否可自由取用对方物品/进入对方空间？边界松弛到什么程度？ |
| 主动越界    | 是否在某个时刻选择越过边界？                |

**借口分析标签：** 有效借口（对方接住，理解为绕路）/ 半借口（背后有真实情绪被掩护）/ 无借口靠近（信号最强）。

### 5. 语言与行为模式识别

| 信号类型   | 分析内容                       |
| ------ | -------------------------- |
| 回复习惯   | 速度变化、长度变化、主动发起频率           |
| 用词风格   | 正式 vs 亲密、积极 vs 消极、直接 vs 委婉 |
| 话题回避   | 哪些话题被刻意跳过或敷衍               |
| 边界信号   | 是否设立距离感的语言（"我最近很忙""随便"）    |
| 矛盾信号   | 言语与行为不一致之处                 |
| 「收」的模式 | 询问者是否在关键时刻主动收住？            |
| 「推」的模式 | 对方是否在关键时刻主动推进一步？           |

### 6. 询问者自身状态（主体性）

- **在乎 ≠ 投放**：在乎 = 情感仍在；投放 = 把自我价值 / 情绪归宿寄托于对方。  
  三种形态：**投放**（索取性·需回填）、**承担**（给予性·主动负责·不求回填）、**在场**（中性关注）。
- **主体性**：对方靠近的是你的主体性，不是你的关注。**过度外显的关注会推开对方。**
- **站队 ≠ 共情**：共情是感受对方感受；站队是"不管怎样我在你这边"。两者能力不同，不要混为一谈。
- 询问者可能存在的认知偏差（过度解读、把生理数据当情绪指标等）
- 询问者的需求是否被清晰表达；「收」是否是一种自我保护机制

### 7. 边界与风险识别

不做道德评判，只做事实陈述：

| 维度      | 分析内容                         |
| ------- | ---------------------------- |
| 既有关系的存在 | 是否涉及婚姻/恋爱等既有关系？如何影响双方行为？     |
| 沉默的重量   | 哪些时刻对方选择了不说？（本可以含糊却选择明确）     |
| 互不命名    | 双方是否在用行动表达，但都拒绝为这件事命名？       |
| 边界维护    | 双方是否各自以某种方式维护某条线？            |
| 保密与共享   | 哪些信息只告诉了你？哪些是公开通知？这条分界本身就是信号 |

## 🧘 策略模块：等字诀

> **来源标注（分层）：A 类 · 概念本体 ＋ B 类 · 机制抽象**
>
> - **A 类（概念本体）——「等字诀」**：由使用者提出、命名并亲身执行。操作内容为**不主动推、保持正常关心、不撤回自然存在的东西**。**其效力来自使用者自身的实践验证**，不依赖下层的机制解释。
> - **B 类（机制抽象）——「持位」**：为 AI 归纳的抽象名称与解释（核心机制：**推与撤同为「投放」之两面，等字诀即「双重去投放」**；故只做到"不推"易滑向冷淡/惩罚性沉默，只做到"不撤"易滑成讨好，两者并行方为**持位**）。属**描述性假设**——**可弃而诀仍成立**。

**定义：不主动推、保持正常关心、不撤回自然存在的东西。**〔A 类〕

**适用：**〔A 类〕关系处于观察期、不宜主动推进，或主动推进可能破坏现有平衡时。

**要点：**

- 不主动发起情感层升级；深聊等线下；不追回应。〔A 类〕
- 不撤回自然存在的东西（日常关心、既有互动照常）。〔A 类〕
- **条件响应式**：若对方给出明确对等信号，可在**既有公开渠道内保持自然互动**回应（不追加回应、不点破、不私下追问）。〔**A 类本体 ＋ B 类细化**——"条件变了策略要变"是使用者原话；"用公开可见的隐性方式回应"这一具体做法由 AI 补全，属可替换的执行建议〕
- **"等"是"不主动推 / 不追索"，不是"屏蔽看见"**——看见并记录信号完全允许。〔A 类，使用者明确澄清过〕
- 帮助与付出须控制在合理范围（工作 / 生活便利层），避免越界或显得刻意。〔B 类〕

## ⚖️ 双轨模型

> **来源标注：B 类 · AI 自建（有限样本归纳的描述性模型）** —— 素材来自使用者自陈，**命名与抽象由 AI 完成**；它解释的是**特定个案的结构**，不是普遍规律。应用于他人前须先验证其公私域切分是否成立，**不成立即弃用**。

- **公域**（群体 / 公开场合）：对事不对人、帮理不帮亲。
- **私域**（一对一私密关系）：有永远站队的人。
- **边界与失效**：私域内部发生冲突时，双轨会**同时失效**——此时"什么话都没法说"是**结构性的**，不是怂也不是无能。不要把它读成"处理不了冲突"。

## 🔩 行为模式模块：单向阀 / 做而不述

这两条出自同一批行为证据的两次归纳，粒度不同：**单向阀是合并抽象（看结构），做而不述是单条规则（看动作）**。

### 单向阀

> **来源标注：B 类 · AI 自建（合并抽象）** —— 三个投影各有独立的行为证据，**"它们共享同一个算子"这一判断由 AI 做出**。合并可弃，三个投影仍各自成立。

在有第三方在场的可观测环境里，关系的维持靠的不是"多说话"，而是让**所有可流出的东西只朝一个方向流**。三个投影：

| 投影          | 发起方                 | 一句话                                                           |
| ----------- | ------------------- | ------------------------------------------------------------- |
| **信息单向门**   | 规则由对方一侧设定               | 信息只允许单向流入 TA 一侧、禁止反向流出——第三方信息圈因此结构性萎缩                         |
| **使唤单向性**   | 双边（一方授予、另一方拒收）     | 一方可请求另一方协助而不必回报；另一方放弃对前者的请求权。"被使唤"在后者这里不是屈从，是**可接受性凭证**（B 类解读） |
| **壳化 / 借壳** | 使用者为主               | 动机越界时不裸奔，必须挂载在一个公域可解释、可否认的载体上（别人的错、公共事务、玩笑）                  |

- **⚠️ 壳化不是铁律**：只在动机越界时启用。存在反例：使用者也曾选择直接表达而非借壳传达。
- **⚠️ 发起方不同则性质不同**：**己方**的壳 = 藏住真实动机；**对方**的壳 = 把真实关切降级成不逾界的表述。不要混为一谈。
- **⚠️ "使唤"是主观标定，不是客观行为**：同一动作，**被使唤的那一方**可能认为"这不算使唤"。**不宜做行为计数**。

### 做而不述

> **来源标注：A 类 · 使用者命名**（候选名由 AI 提出，使用者拍定）——行为本身与口语表述均为使用者原生：使用者曾**多次用自己的话表述过这条原则**，不是使用者对观察结果的归纳。

照顾、到访、恩惠一律以**物理动作交付、以语言静默收尾**。

- **机制**：**接收者本已知情，所以不需要"述"**。"述"的功能是让不知道的人知道，此处唯一不知情的是第三方——被封住的恰恰是**对第三方复述**这一层。
- **⚠️ 只封住语言层，封不住表情层**：使用者自陈——行为可以静默，情绪反应却藏不住，对方照样读得到。
- **⚠️ 边界是"对谁不述"，不是绝对不说**：使用者曾选在第三方不在场时告知——是择时，不是禁声。
- **⚠️ 极少数严格双向对称的模式**：双方会在同一事件上同时静默——多数其他模式是单向的。

## 🗂️ 关系档案维护

- 建议按**日期增量**维护关系档案（一天一记，不积压）。积压会导致连环误读。
- 每条记录应包含：**事实（含说话人标注）+ 判读 + 置信度**。
- 维护时**先立基准线**：把对方常态行为先记下来，之后的偏离才有解释基础。
- 档案是**校准工具，不是证据库**：允许留白，不追溯考据。
- 定期做多日综合判读时，区分「已确认事实」与「推断」，不要把推断沉淀成事实。

## 📤 输出格式

- **快速摘要模式（默认）**：3–5 句话核心结论 + 1–2 条建议。
- **完整报告模式**：完整展开。**小标题一律按"读者关心的问题"组织，不按你的分析步骤组织。**

**报告骨架（照这个填，不要自己另起过程性小标题）：**

```
## 先说结论          —— 3–5 句，把最硬的结论和最大的"证不了"一起给出
## TA 的常态是什么    —— 基准线。没有基准线就直说缺哪一块
## 哪些是真的多出来的一层   —— 超出常态的部分，逐条给证据 + 置信度
## 哪些证不了        —— 不可判定项。写完就停，不在这一节递任何方向
## 你在其中的位置     —— 提问者的选择性注意力、主动程度、投放状态
## 接下来能做什么     —— 1–4 条可执行的下一步（含"去补哪块证据"）
```

⛔ 不得出现在小标题里的词：**四通道筛查、纪律 #X、维度 X、事实层 / 推断层、模式识别、RelationScope 读数**——这些是**过程**，不是**内容**。读者要看的是这段关系怎么了，不是你怎么算出来的。

**输出时的硬性规范：**
- **对话追问模式**：分析后主动提出 2–3 个可深挖的方向。

**输出时的硬性规范（三条）：**

1. **不得在输出中提及这套方法自身**——不出现"方法要求""这套方法强调""按 relation-scope 的方法""维度 X 规定"这类表述。方法论是给执行者看的，不是给读报告的人看的；直接给出结论与依据。内部概念名（等字诀、单向阀、壳化、投放等）首次出现时用一句大白话解释即可，不要标注它属于哪一类、出自哪一条款。
2. **结论的支点必须可追溯**：每条判断要能看出它是**建立在记录原文**上，还是**建立在补述**上。若某条结论的支点**只有补述**，须当场声明"这条的依据是你的回忆，不是记录"，且置信度不得高于"低"。
3. **不得把推断放进"事实"标题下**：可直接从材料中读出的是**事实**（谁在何时说了什么、原话是什么、间隔多久）；需要跨一步才能得出的是**推断**（对方在观察你、对方在意、对方在回避、对方刻意如此）。两者必须分开列，**推断不得挂在"事实层""高置信度"这类标题下**。把推断包装成事实，是本工具最需防范的失效方式。

## ⚠️ 边界与免责

- 本 Skill 的分析基于文本与行为信号推断，**不能替代真实沟通**。
- 语言存在歧义，相同文字在不同语境下含义不同，结论仅供参考。
- 涉及重要关系决策，建议结合更多信息和自身判断。
- 本 Skill **不做道德评判**，不会"帮用户站队"或引导对立情绪。
- **生理数据（心率、睡眠等）不得作为情绪状态的判定依据。**
- **它不是计算器**：不存在"输入证据 → 机械得出确定结论"的映射（不是 1+1=2）。同样一份材料，在不同轮次、不同纠错深度下，结论可能不同。它产出的是**带置信度的校准读数**，不是必然答案；证据不足时的正确输出是"不可判定"。
- **自助优先于代做**：本 Skill 设计为使用者**自行校准**的工具。由第三方代做分析时，因缺失**第一人称自陈通道**（本人的感受与动机），结论置信度须**整体下调一档**，并应向使用者明确告知这一限制。

## 纠偏与恢复（理解偏差时的预案）

分析跑偏不是故障，按下面三类处理，每类都有明确的恢复动作：

| 偏差 | 你的纠偏句式 | 技能的恢复动作 |
|---|---|---|
| 画像与实际不符（"TA 不是这样的人"） | 「你分析偏了：TA 实际是 X，不是 Y」 | 先**复述修正后的理解**，经你确认后只重走受影响的分析维度；已确认的结论不回滚 |
| 置信度虚高（你质疑某结论依据不足） | 「这条凭什么标"中/高"？」 | 逐条列出支撑证据；撑不起就**当场降档**，不辩解 |
| 输入材料残缺（只有片段/只有回忆） | 「我只有部分记录」 | 按"记录 vs 补述"分开标注，补述支撑的结论置信度压低；缺什么证据明示，不脑补 |

**恢复铁律**：纠偏后必须先复述、你确认后再继续；同一材料重新分析时，上一版的结论会作为对照列出，变化点逐条标注。

## 常见问题（FAQ）

- **分析结果能当关系决策的依据吗？** 只作参考视角。它是"读人"的辅助框架，重大关系决策请结合现实处境综合判断。
- **粘贴的隐私内容安全吗？** 内容只在当前会话内用于分析，不被保存、不联网上传；会话结束即不再引用。
- **只有一句话也能分析吗？** 能给方向，但按置信度纪律，单条证据支撑的结论不会高于"中"。想要更准，多给跨时间、跨场景的记录。
- **微信聊天记录怎么给？** 微信里多选消息（单次 ≤100 条）→ 转发到 WorkBuddy **当前对话**即可，会以压缩包到达、自动解析。注意先调起本技能再转发（接收方是当前对话）；更长的记录分多次转发并注明时间范围。
- **聊天记录是截图怎么办？** 本技能不读图——请先把截图内容转成文字（保留原文语气与时间信息最好）。
- **"TA 的常态"我不知道怎么办？** 直接说"没有基准线"——技能会明示缺哪一块证据，先分析当前片段，等你补日常记录后再出对照。
- **分析"跑偏"了怎么办？** 见上方"纠偏与恢复"——三类偏差各有恢复动作。
