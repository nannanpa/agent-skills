# 技能溯源核验（Provenance Audit）

核验已安装技能"从哪来、正不正宗、是否该换源"。**与安全审计分工明确：本技能不查恶意代码，安全疑虑一律转交官方 skills-sec-audit。**

v1.1.0 起新增「实用度核查」，v1.2.0 新增「统一入口 origin.py」——一条命令同时出「正宗度 + 实用度」双维合并报告与综合建议，形成「一站式双支柱体检」；安全仍一律转交官方 skills-sec-audit。

## 对话式触发（推荐用法——普通用户看这里）

**不需要自己敲命令。** 你只要对 AI 说：

- "核验一下这个技能是不是正版"
- "查查 skill 的来源，要不要换源"
- "帮我做一次技能溯源体检"

AI 会自动代为运行 `scripts/provenance.py`、读取结果并**用人话解读报告**（正版/待观察/建议换源 + 理由），你只需要看结论。命令行用法（下节）供想自己跑的用户参考。

## 快速使用

> **推荐：一条命令出双维报告。** 不想分别跑两个脚本？用统一入口 `origin.py`，一次同时给出「正宗度 + 实用度」合并报告与综合建议（详见下文「统一入口 origin.py」）：
> ```bash
> python3 scripts/origin.py <技能目录名>      # 单技能双维体检
> python3 scripts/origin.py all               # 全量双维体检
> python3 scripts/origin.py all --no-network  # 离线：只跑实用度，跳过联网正宗度
> python3 scripts/origin.py all --no-exec     # 严格零网络：连样例脚本都不执行
> ```

```bash
# 核验单个技能
python3 scripts/provenance.py <技能目录名>

# 全量核验（默认扫描根跨平台自动发现，见「扫描根发现」）
python3 scripts/provenance.py all

# 核验自定义目录（批量进度实时显示在终端，不混入报告）
python3 scripts/provenance.py all --dir /path/to/你的技能目录

# 用外部规则文件覆盖阈值/名单（默认读 config/rules.json）
python3 scripts/provenance.py all --rules /path/to/rules.json
```

## 实用度核查（装后质量甄别）

光查「正不正宗」不够——你从市场下的技能「不好使」，往往**不是盗版，而是三类问题**：

1. **真·坏的**：脚本跑不通、依赖缺失；
2. **描述夸大**：吹得能全自动，实际只给几句提示（口号型/demo）；
3. **不匹配需求**：功能本身 OK，但根本不对你的具体场景。

本模块对已安装的技能用**纯本地、零网络**的方式，给每个技能做一次「实不实用」体检，与 provenance 的正宗度互为补充。

### 用法

```bash
python3 scripts/praccheck.py <技能目录名>            # 核查单个
python3 scripts/praccheck.py all                     # 批量核查
python3 scripts/praccheck.py all --dir ~/my-skills    # 自定义目录
python3 scripts/praccheck.py <名称> --need "你的需求"  # 附需求做匹配度评估
```

### 方法论（按序执行，六项检查）

1. **结构齐备**：是否有 SKILL.md（必备）、README、脚本、参考文件。
2. **三件套**（沿用本技能作者的发版纪律——异常处理／FAQ／多场景示例，缺一不发）：脚本是否含异常兜底；SKILL.md/README 是否有 FAQ；是否有示例或代码块。
3. **描述诚实度**：描述若声称自动动作（自动/一键/生成/调用/抓取…），须有脚本或详尽说明支撑；无载体且说明过简 → 疑似口号型/demo。纯提示词型技能只要正文详尽即视为实现支撑，不误伤。
4. **运行风险**：是否依赖第三方库（非开箱即用）、是否含硬编码绝对路径（换机可能失败）、是否需自备第三方凭证。
5. **需求匹配度**（`--need` 时）：以需求关键词与技能文本的字 bigram 重合率做启发式匹配，给出 高／部分／低 匹配，仅供参考，最终由人拍板。
6. **实跑验证**（v1.2.0 新增，纯本地零网络）：对技能脚本做 `py_compile` 编译 + 含 `__main__` 入口的 `--help` 启动探测，并对自带样例脚本（`demo`/`example`/`run_example` 等）实际执行、核对退出码 0 且输出非空——不只证明"能启动"，还要验证"真能跑出东西"。不跑主入口无参调用（避免副作用），仅跑显式样例脚本，超时 8s。

### 质量判定矩阵（实用档位）

| 档位 | 判定条件（评分） | 建议 |
|---|---|---|
| **优** | 结构完整、三件套齐备、描述与实现一致、无运行硬伤（≥85） | 可放心用 |
| **良** | 基本齐备，仅缺某项三件套或有轻微运行提示（65–84） | 可用，看发现项 |
| **慎用** | 描述疑似夸大／零载体 demo／未声明重依赖／硬编码路径（40–64） | 先验证再用于关键场景 |
| **不建议** | 多项硬伤、明显玩具（<40） | 高风险，莫用 |

> 评分起点 100，按缺失项扣分；本模块只给「实不实用」信号，不替代 provenance 的正宗判定，也不替代 skills-sec-audit 的安全判定。

## 统一入口 origin.py（v1.2.0，推荐）

不想分两次跑 provenance + praccheck？`scripts/origin.py` 是两者的统一入口：一次调用，出一份「正宗度 + 实用度」双维合并报告，并给出一句话**综合建议**（✅ 可放心用 / ⚠ 先验证再用于关键场景 / ❌ 不建议用）。

### 用法

```bash
python3 scripts/origin.py <技能目录名>                  # 单个技能双维体检
python3 scripts/origin.py all                           # 全量双维体检
python3 scripts/origin.py all --dir ~/my-skills          # 自定义目录
python3 scripts/origin.py <名称> --need "你的需求"        # 附需求做匹配度评估
python3 scripts/origin.py all --no-network               # 离线：只跑实用度，跳过联网正宗度
```

### 设计要点

- **两维独立、互不影响**：正宗度来自 `provenance.audit_skill`（联网查 GitHub），实用度来自 `praccheck.praccheck`（纯本地零网络，始终可跑）。
- **离线自动降级**：检测不到网络时，正宗度标注「⏭ 离线跳过」，仍完整输出实用度，绝不因联网失败拖垮整体；也可显式加 `--no-network` 跳过探测、秒出。
- **综合建议**：实用度过低（<40）直接「❌ 不建议用」；实用度偏弱或正宗度存疑（D/？/离线跳过）则「⚠ 先验证再用于关键场景」；两维皆稳则「✅ 可放心用」。
- **安全仍转交**官方 skills-sec-audit：本报告只管正宗 + 实用。

## 常见问题（FAQ）

- **批量核验时有没有进度提示？** 有——终端会逐行显示 `[2/8] 核验中: xxx …`（走 stderr，不混进报告表格）。核验要连 GitHub，技能多时耐心等它跑完。
- **GitHub 限流了怎么办？** 报告不会因此误判——限流时档位标为"？ API受限"（**限流≠无背书**，稍后重跑即可，不会误判成 D 档）。v1.2.2 起 403/429 的**全部形态**（二次限流、abuse detection、Retry-After、429 空响应体）均能识别，不再漏判成「仓库不存在」而冤枉成 D 档。等几分钟重跑即可；高频核验可设环境变量 `GITHUB_TOKEN` 提额（默认匿名、零配置开箱即用）。
- **断网了还能用吗？** 能。v1.2.2 起**离线也会给出本地可判项**（自建/改造、市场件背书照判），只把需要联网实测的权威档位（B/B-/A+/C）标为「？ 上游未查询」，联网后重跑即可补全。断网原因也分开报：限流（？ API受限）等配额恢复，网络不可达（？ 网络不可达）则改网络。
- **「置信度」怎么读？** 它不是给档位打折，而是告诉你**这条结论有多硬**：高＝GitHub 公开数据实测（可复核、有时间戳）；中＝本地元数据/名单/台账（未与平台核对，可被伪造）；低＝证据不足或未能取证。所以「A 官方背书（置信度中）」不等于「A+ 厂商官方（置信度高）」的分量。
- **厂商白名单（A+ 档的依据）怎么维护？** v1.2.2 起**不必改代码**——直接编辑 `config/rules.json` 的 `official_orgs` 即可（也可 `--rules <路径>` 或环境变量 `SKILL_ORIGIN_RULES`）。默认值与 v1.2.1 完全一致，零配置行为不变。同一个文件里还能改星数阈值（`top_star`/`low_star`）、自建名单（`self_built`）与命名空间（`own_namespace`）。
- **别的平台/别的 agent 环境也能用吗？** 能。默认扫描根现在**跨平台自动发现**（WorkBuddy / Claude Code / ~/.config / ~/.codex / ~/.agents / ~/.gemini / Windows %LOCALAPPDATA%、%APPDATA%），报告抬头会写明本次扫的是哪个根；仍可用 `--dir` 覆盖，也可用 `SKILL_ORIGIN_SKILLS_DIR` 环境变量固定。
- **本技能做签名校验吗？** **不做**。没有通用签名方案，A/A+ 档基于本地未签名元数据或 GitHub 公开数据，**不构成供应链完整性保证**。这一点刻意写明，不假装覆盖。
- **实跑验证会真的执行我的脚本吗？** 会执行**显式样例脚本**（`demo`/`example`/`run_example` 等），但 v1.2.2 起执行时**注入阻断外网的代理环境并清除 `GITHUB_TOKEN`**，子进程发不出网络请求；不跑主入口无参调用。要完全不动任何脚本，加 `--no-exec`。
- **报错看不懂？** v1.2.2 起所有受控失败都带统一错误码，形如 `❌ [E_DIR_NOT_FOUND] 扫描目录不存在或不是目录：/path`。常见码：`E_DIR_NOT_FOUND`（目录不存在）、`E_DIR_UNREADABLE`（目录读不了）、`E_ARG_MISSING`（参数缺值）、`E_NET_UNREACHABLE`（网络不可达）、`E_NET_RATE_LIMITED`（限流）、`E_EXEC_TIMEOUT`（脚本超时）、`E_DEP_MISSING`（缺依赖）。
- **想核验别的目录（比如自己另存的技能仓库）？** 用 `all --dir 目录路径`，任意含 SKILL.md 的目录都能扫。
- **提示"目录下无 SKILL.md"**：传入的不是有效技能目录。技能的标志是根下有 SKILL.md。
- **实用度核查需要联网吗？** 不需要——`praccheck.py` 纯本地读技能文件，零网络、零依赖，任何时候都能跑；只有查「正不正宗」时才用 `provenance.py`（联网查 GitHub）。样例脚本执行期会阻断外网（见下条）。
- **实用档位和正宗档位什么关系？** 两个独立维度。一个技能可能「正宗但不好使」（官方出品却不匹配你的需求），也可能「好使但来路存疑」。装之后两个都过一遍最稳。
- **`--need` 匹配度准吗？** 是字 bigram 重合的启发式，只作参考；它帮你在装之后先排除明显不匹配的技能，但最终是否匹配你的真实场景，仍由你判断。
- **origin.py 和分别跑 provenance/praccheck 有什么区别？** 结果完全一致——origin.py 直接复用两个脚本的核心函数，只是把两维合并成一份报告并给综合建议；想要更细的单维报告（如只看溯源明细）仍可直接跑 provenance.py / praccheck.py。
- **origin.py 联网失败时怎么办？** 自动降级：正宗度标注「⏭ 离线跳过」，实用度照常输出；联网后重跑即可补全正宗度。也可加 `--no-network` 显式只跑实用度、秒出。
- **"自建/改造"判词为什么不再写"原创度100%、不存在正版问题"？** 因为判据是本地未签名的 `_skillhub_meta.json` / `SELF_BUILT` 名单 / 本地台账，均未与平台核对、可被伪造。新判词显式写明"均为本地证据、未与平台核对，可被伪造——不证明原创、不构成授权依据"，把不确定性摊开给你看，而不是假装下了铁结论。
- **安装元数据损坏会让整批核验崩掉吗？** 不会。`_skillhub_meta.json` 写成非 dict（如 JSON 列表/字符串）时，该技能降级为「？ 核验异常」并继续下一个，整批扫描不中断（F-3）。
- **正文里提到某个仓库（比如 anthropics/skills）会被判成厂商官方吗？** 不会。仅"提及"某仓库不进入档位判定，只展示、不授 A+ 厂商官方背书；需有明确来源声明词或作者 URL 才算来源（F-1）。

## 核验方法论（按序执行）

1. **收集来源线索**（三处）：
   - `_skillhub_meta.json` → `source` 字段（`marketplace`=官方市场，`skillhub`=第三方市场）＋ `installedAt` 安装时间戳
   - `SKILL.md` 的 `author`/`version` 字段
   - `README.md`/`SKILL.md` 中的 GitHub 仓库链接（排除 `user-attachments`、`github.com/search` 等非仓库链接）
2. **GitHub 公开数据溯源**（`https://api.github.com/repos/{owner}/{repo}`，匿名公开接口，无需注册）：星数、`fork` 字段、`parent`（fork 必查母仓）、`pushed_at` 最后更新
3. **套用判定矩阵**（下表）出档位与建议
4. **输出报告**（md 表格：技能 / 来源 / 上游仓库 / 星数 / fork / 最后更新 / 档位 / 建议）

## 判定矩阵（核心规则）

| 档位 | 置信度 | 判定条件 | 含义与建议 |
|---|---|---|---|

> **置信度含义**（v1.2.2 新增）：**高**＝GitHub 公开数据实测（可复核、有时间戳）；**中**＝本地元数据/名单/台账（未与平台核对，可被伪造）；**低**＝证据不足或未能取证（网络受限、来源未声明、无线索）。**它不是给档位打折，而是告诉你这条结论「有多硬」**——「A 官方背书（置信度中）」与「A+ 厂商官方（置信度高）」的可信分量并不相同。

补充规则：
- **fork 判定只看 GitHub `fork` 字段**，不猜；fork 版一律查 parent，母仓星数远高于 fork（10 倍以上）→ 明确建议换母仓
- **新鲜度**：`pushed_at` 晚于本地 `installedAt` → 提示"上游有更新"（按本地时区日期比较）；改造类技能提示走 UPSTREAM-MERGE 三方合并（上游当底料、本地改造优先、bug 修复直接吸收）。**仅日期粒度不足时须按提交级比对**——版本号不变而内容已进（实证：book-to-skill 基线落后 30 笔，pyproject 仍为 1.4.0），此时用 GitHub API 逐笔列上游提交、与本地基线 commit 比对，得出"待吸收 commit 范围"
- **★上游基线纪律 U1/U2（2026-11-02 立规，全域适用）**：
  - **U1 生产必用开发时最新基线**：基于上游 skill 生产新技能时，基线必须是开工那一刻的上游最新**提交**（非历史版本、非"上次装过的"、非"版本号更大的"）。判断基线用 `git -C <安装目录> log -1` + 上游 API 比对，**版本号只作参考不作判据**。
  - **U2 发布前必再扫一次上游**：任何技能发布前（首发／改版重发／分享包重打）必须重新扫上游提交，结论显式落笔三选一——**①吸收**（记 commit 范围）／**②不适配**（记理由与依据）／**③上游无更新**（记扫描时间与 commit）。只写"已检查"不写结论＝未完成。
- **限流≠无背书（防冤案铁律）**：匿名调用限 60 次/时，超限时输出"？ API受限"档而非 D 档；日常核验频次下足够
- **零结论铁律**：GitHub 镜像 0★ 不等于技能没用（SkillHub 等市场可能有大安装量），反之市场热卖也不等于开源侧有审查——两个信号都报，让用户拍板
- **坏元数据不崩批**：`_skillhub_meta.json` 非 dict（列表/字符串）时，单个技能降级为「？ 核验异常」并继续，不拖垮整批扫描（F-3）
- **提及不等于来源（F-1）**：正文仅"提及"某仓库（如"可参考 anthropics/skills 的写法"）不进入档位判定，只展示、不授 A+ 厂商官方背书
- API 未限流时优先 api.github.com；github.com 网页在本机可能被限流，不用它
