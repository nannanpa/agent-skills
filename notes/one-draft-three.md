# 一稿为三

> 一份公文写完，同一批材料按看的人拆成三份——原件、参谋件、对外件。边界写进文件头，不靠记性守。

---

## 给新读者（可直接粘贴）

本笔记不单独成 skill，是一条独立的实操口径，可脱离任何工具使用。把下面这段直接贴给你的 agent（WorkBuddy / Codex / Claude Code 均可）：

```
我有一份已写好的公文材料，请按"一稿为三"走一遍：
1. 按看的人切成三份：原件（真人名、内部判断、日期全留）、参谋件（人名换代号、判断带置信度）、对外件（全脱敏，涉人只留职务履历）。
2. 每份文件头写死边界：原件"只在原工作区用，不转发"；参谋件"只作参谋输入，落纸一律脱敏"；对外件"个人动态不进，须经核稿人终审"。
3. 示例一律虚构；真实人名、未定稿判断、内部意见不得出现在对外件。
4. 你不自动判定什么能公开——终审归核稿人。
输出：三份文件＋各自边界声明。
```

说明：本笔记 MIT，与任何上游公文 skill 无版权连带；示例全为虚构公文，不含真实人事材料。

---

## 它管什么

公文写作的技能已经很多：起草、润色、格式、核稿。但"写完之后这份东西能给谁看"这一步，多数工具不管——它靠使用者的记性守，而记性在赶稿时最不可靠。

**它不管怎么写、怎么排版、怎么核稿，只管这份写好的东西能给谁看。材料不敏感时，它没有存在的必要。**

输入是一份**已经写好的材料**，输出是三份文件，各自带边界声明。不负责起草、润色、格式（那是写作类和 docx 类技能的活）。

## 三步用完

把材料贴进来 → 说"按一稿为三切三份" → 拿走三份文件，分别使用。**你必须自己决定哪一份给谁**——它不替你判断什么能公开。

## 三层怎么切

| 件 | 内容 | 文件头铁律 |
|---|---|---|
| 原件 | 真实人名、内部判断、日期全留 | 只在原工作区用，不转发 |
| 参谋件 | 人名换代号、判断带置信度 | 只作参谋输入，落纸一律脱敏 |
| 对外件 | 全脱敏、涉人只留职务履历 | 个人动态不进，须经核稿人终审 |

**为什么是"物理分三份"而不是"一份材料里标敏感段"**：同一份文件里的敏感段，复制的时候一定会被整段带走；分成三份文件、每份头两行写死边界，传播时边界跟着文件一起走。这是它和通用脱敏工具的根本差别——通用脱敏抹名字，它按受众给同一事实不同形态，**靠文件隔离守边界，不靠人记**。

## 三条硬红线

1. **不自动判定公开范围**。对外件只做脱敏，终审归核稿人。理由：工具不知道这份材料在什么场合、对谁、以什么身份发出去——它看到的是文本，看不到语境。
2. **默认不做红头**。除明说"发文版式"，只留标题＋正文＋落款。理由：红头是"以单位名义对外发文"的标识，内部讨论稿套红头会造成"已定稿对外文件"的误读。
3. **示例一律虚构**。用"关于某学科增设硕士点的请示"演示三层输出，不用任何真实人事材料。理由：示例本身就是传播载体，拿真材料当例子，作品本身就成了泄密口。

## 边界与不适用

- **强的场景**：同一批人事判断，原件可看、写文章只能参谋、上会件必须干净——现在靠你记规矩，做成三份文件是靠结构和文件头守。
- **弱的场景**：材料本身不敏感时，它就是多此一举；对方只要"把这份东西写干净"，用 docx 类技能更直接。
- **不做的事**：起草、润色、格式、终审。定位写窄，避免被拿"写得像不像公文"来卡。

## 维护方法

新增红线时，写进对应那一层的文件头，不要只写进说明正文——说明正文会被跳过，文件头不会。每次改完，用虚构材料重新走一遍三份输出，确认对外件里没有真实人名。
