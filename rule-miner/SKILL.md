# Rule Miner（知识盘点与挖掘）

## 一、定位与内涵

### 1.1 名字为什么叫 Rule Miner
"Rule" 取英语**广义**——**规律 / 法则 / 经验法则（rule of thumb）**，不限于中文"规章制度"的窄义。凡能从工作记录里淘出、能回填长期记忆、避免重复学习的**陈述性知识资产**，都在此列。

它与 `skill-miner`（挖**程序性技能**：怎么做）成对：
- **本技能**挖"什么成立 / 什么该守 / 什么坑"（what / why / constraint）→ 陈述性知识；
- **skill-miner** 挖"怎么做"（how）→ 程序性技能，产出 SKILL.md 骨架。

二者资产类型不同，故本技能独立成体、不被并入 skill-miner。

### 1.2 五类可提取资产
| 类型 | 含义 | 实例 |
|---|---|---|
| **硬约束** | 必须守的铁律 | 涉密不出本地、单文件≤50KB |
| **方法论** | 可复用的思考/操作框架 | 先核验再提取、廉价优先 |
| **坑与教训** | 踩过的雷、反面教材 | 对可复制 PDF 误用 OCR 丢版式 |
| **模板范式** | 常见结构/写法套路 | 函件三层（函/任务书/prompt） |
| **决策判据** | 何时选 A 还是 B 的标准 | skill 超界优先扩描述而非改名 |

### 1.3 出身（origin）
本技能由 agent 在"全盘盘点 4211 个 .md 找漏提规则"任务中**主动萃取**，非用户预先吩咐。这一出身坐实了它的独立性：它有专属 origin、挖的是陈述性资产，不应被任何程序性技能吞并。

### 1.4 与 skill-miner 的区别
`skill-miner` 挖可复用的**技能**（产出 SKILL.md 骨架）；本技能挖任意 .md 里的**知识资产**（产出记忆分册更新）。对象与落点均不同，互补不重叠。

## 二、何时触发 / 不触发

**触发**：
- 用户说"扫一遍有没有漏提的可复用规则/知识资产""盘点全盘 .md 提取沉淀""把任务里的规则提炼进全局记忆"。
- 用户怀疑"之前某次任务沉淀的东西没进全局记忆"。
- 定期（如每月）主动巡检，防止知识沉死。

**不触发**：用户要的是读取/编辑某个具体文件内容（那是普通文件操作，不是盘点提取）。

## 三、六步流程

### Step 1 廉价枚举（scripts/scan.py v2.2）
执行 `python3 scripts/scan.py [--root DIR]`。脚本**不做语义解析**——只统计字节与行数（计行需逐行读取，I/O 与文件总字节同阶，但不进模型上下文），输出：① **全盘 .md 分布（不含已排除的噪声目录）与候选分布**两段（根目录文件归入 `(根目录)`）；② 命中知识资产类关键词的候选清单（大→小排序），**每条带资产类型提示**（按相对路径匹配关键词，目录名同样参与）。

- v2/v2.1 参数：
  - `--root DIR`：限定扫描根（默认 `~/WorkBuddy`）；局部盘点用 `--root <任务目录>` 只扫该目录。
  - `--kb DIR`：顺带检索指定知识库（如 `~/WorkBuddy/记忆分册`），标 `KB_HIT` / `NEW` / `KB_ERR`（已出现 / 未命中 / 核验失败）。**v2.1 起 KB_HIT 同时带回知识库命中原文片段 + 初步矛盾分级（高/中/低）**；**v2.2 起片段附 `文件:行号` 出处**，供人工裁决直接看到双方材料。
  - `--json`：机器可读输出，供 dry-run 预览下游消费。
  - `--out FILE`：将报告写入文件（不指定 `--json` 为文本、指定则为 JSON），便于留痕。
- 若脚本不可用，回退为 Bash：`find ~/WorkBuddy -name '*.md' | grep -vE '/(记忆分册|node_modules|dist|novels|chapters|works|references|docs|blob|archive|_orig)/'` 再用 `wc -c` 量体积。
- 噪声区（小说章节/文献 references/node_modules/dist/works）直接跳过，**不要全读**——全盘常有过千 .md，全读既不可能也反噬算力。

### Step 2 分布研判与噪声排除
看分布输出，定位**知识资产富集区**（通常：根目录策展文件、`合议沉淀/`、`核查清单/`、`交接-增量/`、命名含"机制/规整/自检/门禁"的任务文件）。排除已明确无复用的噪声。

### Step 3 grep 核验 + 去重/冲突检测（v2 核心增量）
对每批候选，先用 grep 反向核验它要提的内容是否**已在**记忆分册/MEMORY.md：
```bash
grep -rliE '候选关键词' ~/WorkBuddy/记忆分册/ 2>/dev/null
grep -cE '候选关键词' ~/.workbuddy/user-*/MEMORY.md 2>/dev/null
```
判定三态：
- **已覆盖**（语义重复）→ 跳过，零净增（省阅读算力）。
- **KB_HIT 但语义冲突**（与已有条目相矛盾）→ 标**冲突**并附 `scan.py` 抽回的知识库原文片段与初步分级（高/中/低），**交人工裁决，不静默并入**。
- **零覆盖 / 部分覆盖** → 进入 Step 4（部分覆盖只提缺失部分）。

> 冲突检测是本技能相较"纯搬运"的最大增量（v2.1 升级）：v2 只做"关键词标红交人工"；v2.1 起脚本自动抽取知识库命中原文片段并给初步矛盾分级（高＝命中词出现且原文含否定词，疑似矛盾；中＝可能重复/重叠），把"grep 标红"变成"抽取双方原文＋初步分级"，最终语义冲突仍由人裁决——多数提取工具只会复制，本技能会拦下自相矛盾的条目。

### Step 4 精读净增候选 + 结构化标注 + 溯源（v2）
只读**净增候选**（通常几 KB~几十 KB）。提取时：
- **脱敏**：去除人名/单位/金额/具体模型名/内部系统代号，改写为通用判据级表述（如"某第三方 skill 装前须审计"而非"XX 装前须审计"）。
- **只提 reusable 机制**：通用规则/纪律/判据/流程/模板，不提一次性任务归档、特定公文清洗件。
- **五类标注**：每条标 `硬约束/方法论/坑与教训/模板范式/决策判据` 之一。
- **溯源 + 置信度**：每条带「源文件 + 日期 + 上下文摘要 + 置信分（1–5，按跨源频次/时效性/具体度）」，使提取结果可审计、不黑箱。
- **大文件先 head 预判**：>30KB 的文件先 `head -60` 判断是否通用机制；若是一次性行业/任务文档且领域无关，直接跳过。

### Step 5 dry-run 预览 + 人工确认（v2）
写盘前先输出预览，等用户确认：
```
将处理 N 条候选：
  · X 条已覆盖 → 跳过
  · Y 条冲突 → 待你裁决（已列出双方原文）
  · Z 条净增（类型分布：硬约束 a / 方法论 b / 坑与教训 c / 模板范式 d / 决策判据 e）
    将并入【落点】
```
用户确认后才写盘。安全默认，也显得像个正经工具。

### Step 6 并入 + 留痕（可配置落点）
- **不新建文件**（除非真的无合适分册）。按主题并入六册之一：协作类→`函件与协作.md`；技能/发版→`技能线与发布.md`；流程/口径→`流程与口径.md`；知识/检索→`知识库与检索.md`；文风→`语言与文风.md`；身份/设备→`身份与设备.md`。
- 并入前读取目标分册，确认插入点、避免重复、确认**单文件不超过 ~50KB 红线**。
- 母本文件**保留不删**（作为含完整案例与脱敏红线的源头）。
- 更新 `INDEX.md` 对应指针（如 K 系列），说明"精华已并进某册"，封死"下次又搜不到"的隐患。
- 在根目录写一份全局可见的盘点报告（如 `全盘可复用规则盘点-YYYY-MM-DD.md`），标记哪些已提、哪些跳过及理由；并 append 工作区日志。
- **发版纪律**：本技能只创建/更新本地技能与记忆，**不擅自发布**到 SkillHub；发布按"攒批（≥3 项或功能新增）"由用户拍板。

## 四、可配置落点（v2 专章）

默认落点 = 用户六册（上述 Step 6）。但放出来给"类你但弱调度"的人用时，落点必须可配：

- **`--sink`（技能级指令，非 scan.py 参数）**：在 Step 6 告诉 agent 把净增资产写到哪——`--sink DIR` 指向用户自己的知识库目录（任意 Markdown 库），`--sink FILE` 指向单个汇总文件（如 `RULES.md`）。`scan.py` 只负责枚举，不接收此参数（此前文档误写为 scan.py flag，v2.1 已对齐）。
- **scan.py `--out FILE`**：将枚举/候选报告写入文件（扫描产物 sink），便于留痕或喂下游。
- 接 IMA 等外部 KB：导出为通用 Markdown 后由用户自行导入。
- **敏感兜底（硬门禁）**：涉密 / 内部未定稿 / 含红头原件的材料 → **不碰任何云/外部 KB**，只落本地私有库（记忆分册式），脱敏后才可外发。

> 设计原则：落点可配，但**涉密不出本地**是默认值而非选项——对高校党政机关受众，这是合规底线，不是好习惯。

## 五、关键纪律（来自实战复盘 + v2 增补）

1. **廉价优先**：先枚举+量体积+grep 核验，再决定读不读、读多少。绝不未经筛选全读全盘 .md。
2. **不读噪声**：小说章节/文献/node_modules/dist 等占全盘 90%+，与知识资产无关，跳过。
3. **先核验再提取**：用 grep 确认是否已覆盖，**并检测冲突**，避免重复提取、分册间漂移、自相矛盾。
4. **冲突不静默**：KB_HIT 且语义冲突的条目必须交人工裁决，绝不偷偷覆盖或并存。
5. **脱敏并入、母本保留**：合并版去敏感信息；母本原样留作源头。
6. **单文件 ≤ ~50KB、不新建文件**：复用现有分册，超阈值才拆分（参考用户历史阈值：规则类 50KB、工作文档 24KB 归档）。
7. **溯源必带**：每条净增都带源文件/日期/置信度，可审计。
8. **跨会话可追溯**：盘点报告放根目录（非任务本地），防"沉死"。

## 六、异常处理（三件套之一）

- **扫描失败 / 权限拒绝**：核对 `~/WorkBuddy` 路径是否存在、是否被 iCloud 未下载占用；改用 `ls` 逐层探明，不在未确认时递归删/改。
- **目录过大导致超时**：缩小扫描根（如只扫 `~/WorkBuddy/记忆分册` 与几个已知沉淀库），或先 `find` 限定 `-maxdepth 3`。
- **记忆分册读不到 / 缺失**：先确认六册是否移位；若 `记忆分册/` 不在预期位置，向用户确认路径，不臆造落点。
- **grep 误判"已覆盖"**：grep 命中可能是字面相似而非语义覆盖。核验时须读命中上下文 2~3 行确认；宁可多读一条，不漏提真缺口。
- **冲突裁决僵局**：若用户也无法判定新旧条目谁对，两条并存并标"待复核"，不强行二选一。
- **提取后单文件逼近 50KB**：停止并入，改为新建同主题第二册或用户拍板拆分，绝硬塞。
- **scan.py 工程级报错（v2.1，满足三件套·异常处理脚本工程级要求）**：`--kb` 目录不存在 → 中文报错 + `exit 2`；扫描根不存在 → `exit 2`；**扫描根不可读（权限拒绝）→ `exit 3`**；**子目录权限拒绝 → 逐目录 stderr 告警后继续**（不漏扫、不静默）；`--out` 写失败 → `exit 4`；知识库目录不可读 → 告警并降级为 `KB_ERR`，不冒充 `NEW`；逐文件读取错误跳过并告警；未知参数由 `argparse` 拦截并给中文用法。脚本技能不再静默吞错。

## 七、FAQ（三件套之二）

- **Q：刚提完不久，要不要天天跑？** 不必。知识沉死是"长期未盘点"问题，不是高频问题；按月或"用户怀疑有遗漏"时跑一次即可。
- **Q：和 `skill-miner` 什么区别？** `skill-miner` 挖**技能**（程序性，产出 SKILL.md 骨架）；本技能挖**知识资产**（陈述性，产出记忆分册更新），对象更广（含决策记录、协作协议、核查清单等）。
- **Q：rule 不是"规则"吗，怎么还挖方法论/坑？** 取英语广义：规律/法则/经验法则（rule of thumb），不限于中文"规章制度"。五类资产全是陈述性知识，归在此名下正合适。
- **Q：会不会把小说章节/文献也当规则提了？** 不会。Step 1 脚本已排除 `novels/chapters/references/文献/works` 等噪声目录；Scan 输出里命中知识资产关键词的才是候选。
- **Q：冲突检测怎么做的，会不会误报？** v2.1 起：脚本对 `KB_HIT` 自动抽取知识库命中原文片段并给**初步矛盾分级（高/中/低，仅词面启发）**，把"标红"升级为"抽取双方原文＋分级"；最终语义冲突仍由人裁决，脚本不自称判定。宁可多标不漏标。
- **Q：提完会自动发布成 SkillHub 技能吗？** 不会。本技能只产出"记忆分册更新 + 盘点报告"，属本地长期记忆维护；发布按用户发版纪律另行拍板。
- **Q：母本删了会不会丢案例？** 不删。脱敏版进分册供日常命中，母本留作含完整案例与红线的源头，二者互补。
- **Q：跑的时候报错/卡住怎么办？** 对号入座「六、异常处理」：扫描根不存在 → 检查路径拼写或去掉 `--root` 用默认 `~/WorkBuddy`；`exit 3` 权限拒绝 → 缩小 `--root` 到具体任务目录；`--kb` 目录错 → 核对知识库路径（须为目录而非文件）；`KB_ERR` 提示 → 知识库不可读，降级为未核验，**不影响枚举本身**，可换机器或稍后重试。脚本不再静默吞错，报错都带中文"怎么办"。
- **Q：什么时候该停手 / 提前收束？** 三种情况主动收束：① 候选全被 grep 判"已覆盖" → 零净增，不用写盘，回一句"无新增"即可；② 冲突条目多到无法当场裁决 → 只标 `KB_HIT·冲突分级` 交你定夺，不强行并入；③ 目标分册已逼近 50KB → 停止并入，改新建同主题第二册或交你拍板拆分。宁可少提、不硬塞、不静默覆盖。

## 八、多场景示例（三件套之三）

完整实战样本见 `references/field-sample.md`，含：4211 个 .md 如何收敛到 3 个富集区、哪些是净增提取（合议沉淀/引流贴核查/装前安全审计/复盘层判定）、哪些经 grep 核验确认已覆盖而跳过（决策方案采购纪律、SkillHub 上传 409）、以及 62KB 大文件如何 head 预判后跳过。v2 增量（五类标注、冲突检测、dry-run）示意见该文件「七、v2 增量示例」节。

**最小触发样例**（用户原话）：
> "你上一个工作干完了吗？…… 全盘巡检一下 .md，看看还有没有被忽略掉的可复用规则或机制。"

**标准动作**：跑 `scripts/scan.py [--kb DIR]` → 看分布锁定富集区 → grep 核验+冲突检测 → 精读净增并五类标注+溯源 → dry-run 预览等确认 → 脱敏并入对应分册/可配置落点 → 写根目录盘点报告 + 更新 INDEX 指针。
