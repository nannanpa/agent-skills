# 实战样本：首次全盘巡检（2026-10-31）

> 本文件是 rule-miner 的"多场景示例"配套，记录一次真实跑通的巡检，供后续调用时参照。
> 含具体数字与判定，已脱敏为通用表述。

## 一、起点规模

全盘 `~/WorkBuddy` 下 `.md` 共 **4211 个**。若全读将严重反噬算力（违反用户"省钱"诉求），故全程廉价优先。

## 二、Step 1–2：枚举 + 分布研判

另用 `find ~/WorkBuddy -name '*.md' -print0 | xargs -0 du -ch | tail -1` 与 `scripts/scan.py` 对照可见：
- **噪声区占绝大多数**：金庸/民法典小说章节（各约 85 篇）、`node_modules` 文档、`skillhub-publish` 的 dist 产物、学术文献 `references`。这些与可复用规则无关，脚本枚举时已排除，直接跳过。
- **规则富集区仅三块**：根目录策展文件、`合议沉淀/`、`核查清单/`，外加个别任务里的"机制/规整"文件。

## 三、Step 3：grep 核验已覆盖

对候选逐批 grep 记忆分册与 MEMORY.md：
- `合议沉淀/`（多端异步协作治理协议：规则六件套/题面模板/记账机检/分歧台账/端侧挂载/复核提醒/八错例/脱敏红线）→ **六册零覆盖**，且 INDEX 虽有 K5 指向源文件夹但未含精华。
- `核查清单/引流贴核查清单`（信息可信度核查方法论 + 动手陷阱表）→ **六册零覆盖**。
- 根目录 `决策/方案`（采购/API/永久 token 纪律）→ MEMORY.md 命中 4 处、分册已覆盖 → **跳过不提**。
- `纪律-SkillHub上传机制`（409/异步落库）→ 技能线与发布.md 第 38/40/160–183 行已详尽覆盖 → **跳过，零净增**。

## 四、Step 4–5：净增提取

| 源 | 判定 | 处置 |
|---|---|---|
| `合议沉淀/` | 净增 | 脱敏并入 `函件与协作.md` 新节「★多端异步协作治理协议（脱敏通用版）」 |
| `引流贴核查清单` | 净增 | 脱敏并入 `知识库与检索.md` 新节「★信息可信度核查方法论（脱敏通用版）」 |
| `核查清单/审计-*.md`（装前五项安全审计） | 净增 | 脱敏并入 `技能线与发布.md`「★装第三方 skill 前安全审计清单」 |
| `现有技能复盘机制适配性研判` | 净增 | 脱敏并入 `技能线与发布.md`「★技能复盘层建设判定」 |
| `决策/方案` 6 文件（82KB） | 已覆盖 | 跳过 |
| `纪律-SkillHub上传机制`（3KB） | 已覆盖 | 跳过 |
| `数据整合与自动化报告生成机制`（62KB/1658 行） | 领域无关 | `head -60` 预判为"媒体行业数据湖/ETL 架构"文档，与高校行政无复用 → 跳过 |

## 五、留痕

- 三册记忆文件合并后分别约 17.6KB / 9.7KB / 34.6KB，**远低于 50KB 红线**。
- 母本 `合议沉淀/`、`核查清单/` **保留未删**。
- 根目录写 `全盘可复用规则盘点-2026-10-31.md`（全局可见，防沉死）。
- `INDEX.md` K17 加注"两批精华已并进册"，封死下次搜不到的隐患。

## 六、经验要点

1. **先核验再读**：本样本靠 grep 省掉了约 147KB 的无效阅读（决策方案 82KB + 上传机制 3KB + 大文件跳过）。
2. **大文件 head 预判**胜过全读：62KB 文件 60 行即判领域无关。
3. **脱敏是能进全局记忆的前提**：含人名/单位/金额的母本只能留作本地源头，合并版必须通用化。
4. **单文件红线是硬约束**：并入前必看目标册体积。

## 七、v2 增量示例（2026-10-31 升 v2）

v2 在原有"廉价枚举→核验→提取→并入"上，补了四项智能。以本回合真实场景示意：

### 1. 五类资产标注
原样本里四批净增，按 v2 重新打标：

| 源 | v2 资产类型 |
|---|---|
| 多端异步协作治理协议 | 方法论 + 模板范式 |
| 信息可信度核查方法论 | 方法论 + 坑与教训 |
| 装前安全审计清单 | 硬约束 |
| 技能复盘层建设判定 | 决策判据 |

### 2. 冲突检测（示意）
假设 `流程与口径.md` 已有一条"涉密材料可走云 KB"，而新候选"涉密不出本地"与之矛盾：
- 脚本标 `KB_HIT`；
- 人工裁决：新条更严，旧条作废 → 不静默并入，先修订旧条。
- 这正是 v2 相对"纯搬运"的增量价值。

### 2.5 真实冲突裁决记录（脱敏，来自 2.2.x 实战）

- **场景**：候选"单文件≤50KB 红线"与 `流程与口径.md` 已有"规则类 50KB、工作文档 24KB 归档"表述 `KB_HIT`。
- **脚本标注**：`KB_HIT` + 分级 **中**（关键词重合、±20 字符窗口内无否定标记，疑似重复/重叠，非矛盾）。
- **人工裁决**：候选更通用（覆盖"规则类/工作文档"两类），旧条仅列两类特例；**保留旧条、将候选作为兜底判据并入，不静默覆盖旧条**。
- **落点**：`流程与口径.md`「单文件红线」节，标"置信 5（跨多技能印证）"。
- **结论**：本例印证 v2 设计——脚本只标 `KB_HIT·中` 交人裁决，agent 不替用户拍板；这正是相对"纯搬运"的增量价值。

### 3. dry-run 预览（示意输出）
```
将处理 4 条候选：
  · 0 条已覆盖 → 跳过
  · 1 条冲突 → 待裁决（涉密不出本地 vs 涉密可走云 KB）
  · 3 条净增（硬约束 1 / 方法论 2 / 决策判据 1）→ 并入六册
```
用户确认后才写盘。

### 4. 溯源标注（示意）
每条净增带：`源=核查清单/审计-no-wings.md | 日期=2026-10 | 置信=5（跨两技能审计印证）`。使提取可审计。

## 八、场景二：局部巡检（任务工作区收尾挖漏提）

> 与场景一（全盘巡检）形成**两类不同场景**：范围小、频率高、输出是增量回流而非全盘盘点。满足三件套·多场景示例"≥2 类不同真实场景"。

### 触发
用户在某个任务收尾时问："这个任务里沉淀的东西进全局记忆了吗？"或"刚才那轮工作有没有可复用的，顺手提一下"。

### 范围
只扫**该任务工作区**（如 `~/WorkBuddy/2026-10-31-08-50-44/`），**不扫全盘**——数量少、秒级完成，可每次任务收尾跑。

### 动作（Step 1–6 同，但 kb 指向六册、用 --root 限定范围）
`python3 scripts/scan.py --root ~/WorkBuddy/2026-10-31-08-50-44 --kb ~/WorkBuddy/记忆分册 --out /tmp/task_cand.txt`
- 分布研判：任务工作区里通常只有 `*.md` 任务文档，富集区就是根目录与 `.workbuddy/memory/`。
- grep 核验：与六册比对，多数会命中"已覆盖"（任务内沉淀常只是母本，精华已在册）。

### 典型结果
```
将处理 N 条候选：
  · X 条已覆盖 → 跳过（精华早在册，仅母本留本地）
  · Y 条冲突 → 待裁决（如本任务新定的"单文件≤50KB"与册内旧表述措辞不一致）
  · Z 条净增 → 并入对应分册（往往只有 1–3 条真正新的）
```
- 写盘后 append 工作区日志 `.workbuddy/memory/YYYY-MM-DD.md`，**不写全盘报告**（非必要）。

### 与场景一的区别
| 维度 | 场景一 全盘巡检 | 场景二 局部巡检 |
|---|---|---|
| 触发 | 定期 / 怀疑漏提 | 任务收尾顺手 |
| 范围 | 全盘 4211 个 .md | 单任务工作区（秒级） |
| 频率 | 低（月级） | 高（每任务） |
| 输出 | 根目录盘点报告 + INDEX 指针 | 几条并入 + 工作区日志 append |

## 九、可直接跑的命令示例（v2.2.5 新增）

> 回应 2.2.4 评测"补充可执行示例"。以下命令均可直接复制运行（路径换成你自己的环境）。

### 例 1：局部扫描 + JSON 落盘（最常用）
```bash
python3 ~/.workbuddy/skills/rule-miner/scripts/scan.py \
  --root ~/WorkBuddy/2026-10-31-08-50-44 \
  --json --out /tmp/rm-cand.json
```
期望产物 `/tmp/rm-cand.json`，结构要点：
```json
{
  "tool": "rule-miner scan.py",
  "version": "2.2.5",
  "root": "/Users/mabin/WorkBuddy/2026-10-31-08-50-44",
  "all_distribution_desc": "全盘 .md 分布（不含已排除的噪声目录）",
  "distribution_note": "all_distribution 不含已排除的噪声目录（novels/chapters/references/dist/docs/archive 等）；candidate_distribution 仅含命中资产类关键词的 .md",
  "md_total": 20,
  "candidates_total": 20,
  "all_distribution": {"(根目录)": 16, ".workbuddy": 4},
  "candidates": [
    {"path": ".workbuddy/memory/2026-11-02.md", "bytes": 32915, "lines": 142,
     "asset_type": "硬约束", "provenance": "content", "kb": "—",
     "snippet": "", "source": "", "grade": ""}
  ]
}
```
字段说明：`all_distribution` 为全盘 .md 按顶层目录计数；`candidates` 仅含命中资产类关键词者，按体积大→小排序；`provenance=content` 表示由首段内容指纹命中，`name` 表示由文件名命中。

### 例 2：先用自检验证脚本本身没坏
```bash
python3 ~/.workbuddy/skills/rule-miner/scripts/scan.py --selftest
```
期望输出：10 条 `✅ PASS`，末行 `自检结果：全部通过 ✅`，退出码 0。

### 例 3：大目录怕卡死——加超时 + 断点续扫
```bash
# 第一次（若中途 Ctrl-C，进度已写入 progress.json）
python3 ~/.workbuddy/skills/rule-miner/scripts/scan.py \
  --root ~/WorkBuddy --timeout 30 --progress /tmp/rm-progress.json
# 续扫（跳过已处理文件，继续未完成部分）
python3 ~/.workbuddy/skills/rule-miner/scripts/scan.py \
  --root ~/WorkBuddy --resume /tmp/rm-progress.json --progress /tmp/rm-progress.json
```

### 例 4：脚本级 sink（直接把报告交给下游 agent）
```bash
python3 ~/.workbuddy/skills/rule-miner/scripts/scan.py \
  --root ~/WorkBuddy/2026-10-31-08-50-44 --sink /tmp/rm-sink.txt
```
`/tmp/rm-sink.txt` 内容与默认 stdout 报告一致，可直接被下游流程消费。
