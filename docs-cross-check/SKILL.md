# docs-cross-check · 同构材料横切审校（横向一致性复核）

> 版本 **1.0.2**（2026-11-18）｜ 平台 macOS／Linux／Windows ｜ 依赖 `python3` + `python-docx`；无网络、无外部服务
> 范围口径：**只做"横向对得齐"**。单篇内容对不对（事实、引文、口径是否合理），本技能不审、需人工审读把关；修订与批注怎么写进去，归 `docx-track-changes-wps`；文种参数与字数配额，归 `lieflat-gongwen`。各技能获取方式见文末 §十。

---

## 一、定位

**一句话**：N 份同模板材料摆在一起时，把"哪一篇跟别人不一样"在 3 分钟内列出来——**不靠眼睛一篇一篇翻**。

- **四维必做**（本轮只做这四个，其余进 §七 待补）：
  1. **D1 序号连续性**——编号跳号、重号、断在中间；
  2. **D2 目标条格式**——该用"——"体的篇还在用"1./（1）/小标题"；
  3. **D3 篇内重复指标**——同一数值在"目标"写一遍、在"举措"再写一遍；
  4. **D4 篇幅分布**——中位数、极差、超中位 1.3 倍的篇。
- **明确不做**：修订/批注注入（那是 `docx-track-changes-wps`）；单篇事实与引文核验（人工审读层，本技能不碰）；表内单元格内容比对（v1.0.0 不解析表格，见 §六）；**两份不同文档的版本 diff、合同与附件的对齐核对**——本技能全部判据都依赖"同构集"，非同模板的两份文档拿去比，判据会全数失效却不报错。
- **为什么这四个先做**：它们占"17 篇一起核"这件事的 80% 工时，且全部可机器判；剩下的（口径是否合理、指标是否自洽）必须人看。

## 二、触发与开局

典型触发语：横切复核 / 多篇一致性 / 17 篇一起核 / 格式归一 / 序号连不连续 / 篇幅对比 / 同构材料。

开跑前先做两件事：

1. **圈定同构集**：只放"同一模板、同类对象"的篇。混进别的模板（如附件、汇总表）会污染篇幅中位数。
2. **设定技能目录**：后续命令用 `$SKILL_DIR`，由调用方一次注入，技能不猜路径：

```bash
export SKILL_DIR="$HOME/.workbuddy/skills/docs-cross-check"   # 按宿主约定改
```

解释器带 `python-docx` 即可。DSH 侧用内置运行时（`python3 -c "import docx"` 失败时换它，路径见宿主文档）。

## 三、跑法（两条命令）

```bash
# 逐篇体检：段数 / 字数 / 序号项 / 目标条 / 问题数
python3 "$SKILL_DIR/scripts/hecha.py" doc  材料目录/*.docx

# 横切：篇幅表 + 篇内重复指标 + 跨篇金额类
python3 "$SKILL_DIR/scripts/hecha.py" cross 材料目录/*.docx

# 机读（喂给下游或存档）
python3 "$SKILL_DIR/scripts/hecha.py" cross 材料目录/*.docx --json
```

`--json` 输出结构（字段名逐字以此为据，喂下游不要另猜键名）：

```json
{
  "篇数": 6,
  "篇幅": [{"文件": "XX学院.docx", "字数": 9133}, {"文件": "YY学院.docx", "字数": 4054}],
  "篇幅_最小": 4054,
  "篇幅_中位": 9133,
  "篇幅_最大": 14273,
  "超中位1.3倍": ["ZZ学院.docx"],
  "篇内重复": [{"文件": "XX学院.docx", "数值": "15项", "次数": 2}],
  "跨篇金额类": {"500万元": {"出现篇数": 3, "总次数": 4}}
}
```

> `篇幅_中位` 在少于 5 篇时为 `0`（表示"未报"，不是"中位数为 0"），下游判读须按此口径。

退出码：`0` 全过；`1` 有告警（有输出就要逐条看）；`2` 参数或依赖错误（含文件打不开）。脚本报错一律按 `[E<编号>] 原因 → 我已做的 → 需要你做的` 输出：

| 错误码 | 触发 | 处置 |
|---|---|---|
| E1 | 缺 python-docx | 换带依赖的解释器或 pip install，见脚本提示 |
| E2 | 文件不存在 | 报出路径，补齐后重跑 |
| E3 | 混入非 .docx | 整批中止、不静默过滤、不出部分结论；转 .docx 后整批重跑 |
| E4 | 是 .docx 但打不开／内容损坏 | 整批中止并点名文件；修好或剔除后整批重跑（不可只跳过这一篇，否则篇幅中位与跨篇重复会偏）|
| E5 | 是 .docx 但已加密／受密码保护（OLE2 容器） | 整批中止并点名文件；先解密（输密码打开后另存为明文 .docx），或剔除后整批重跑——另存救不了加密，与 E4 的修法不同 |

常见问题与处置合集见 `reference/FAQ.md`。

## 四、判据（可直接当验收表用）

| 编号 | 判据 | 基准 | 命中后怎么处置 |
|---|---|---|---|
| D1 | 编号在"同一列表"内必须严格 +1；允许从 1 重新起（新列表） | 全文顺序扫描 | 跳号→补回或改号；重号→确认删哪一个 |
| D2 | 目标条统一以 `——` 起头，一句话一条 | 含"目标/指标"的段落数 vs `——` 段落数 | 关键词有、破折号 0 → 该篇未归一 |
| D3 | 金额／比例／两位数以上数量，同篇出现 ≥2 次 | 同一数值计数 | 多为"目标写一遍、举措再写一遍"→ 决定留哪处 |
| D4 | 篇幅围绕中位数，超 1.3 倍单独看 | 字数（**去空白**） | 不是硬线；超线先问"多出来的是不是重复"。**少于 5 篇不报中位**——两篇时中位就是较大那篇，没有意义，只看极差。**偶数篇取中间两值平均**（如 4 篇 100/200/300/400 → 250），不取上中位 |

**字数口径**：一律**去空白计**，全程不变。换口径＝换结论，这一条写进报告头。

## 五、反例（看到这个就说明错了）

- 把 17 篇的序号当成"一条连续列表"算 → 每篇各自从 1 起，报一堆假跳号。
- 用**文件名**排序当编号顺序 → 文件名里的 01/07 是学院序号，不是节内序号。
- 篇幅按"含空格字数"比 → 各篇格式不同，差出来的全是排版空白。
- 按"篇均字数"定线 → 同构集里本来就允许有长短篇，只用中位数＋极差提示。
- 把 `1个`/`2项` 的重复当问题 → 通用量词，无信息量（脚本已按 §四 D3 过滤）。

## 六、已知局限（v1.0.0，如实登记）

1. **表格内序号不解析**：`doc.paragraphs` 不含单元格文本；表体编号需人工看。
2. **D2 靠关键词**：完全不用"目标/指标"字样、纯小标题体的篇会漏判（实测 17 篇里 7 篇该归一，脚本命中 6 篇）。
3. **不与修订族共存**：读的是"接受修订后"视图（`w:t`），未接受的 `w:ins`/`w:del` 不影响文本，但也不单独计数——修订痕迹请交给 `docx-track-changes-wps`。
4. **只吃 .docx，这是判据决定的，不是格式偏好**：四维全部建立在"顺序可靠的段落文本流"（`doc.paragraphs` 的 text＋style）上——D1 靠段首编号、D2 靠段落样式、D4 靠去空白字数、D3 靠全文正则。换格式就没有对应物，不是"没做"，是"换了尺子量不了"。
   - **`.doc`：用户侧显式转，不进技能**。`.doc → .docx` 是无损结构转换（同一排版引擎的两代格式），转完四维照常跑；但转换结果随工具/版本变（Word／LibreOffice／`textutil` 对页眉页脚、分栏、软换行处理不同），若技能内部偷偷转，同一份文件在不同机器上判据不可复现。转换指令：macOS `textutil -convert docx -output X.docx X.doc`，Windows 用 Word 另存为，Linux `soffice --headless --convert-to docx`；转换件与原件同目录，复核只针对转换件，且须被明确指认。
   - **PDF：不支持，也不给转换指引**。排除理由是技术性的，不是"不可编辑"（复核是只读动作，`hecha.py` 从不写回）：PDF 存的是带坐标的版面流，转文本时换行、分页、分栏会打乱段落顺序，而 D1／D4 恰恰依赖顺序与完整文本，同一份用不同工具提取结论对不上——判据失去可复现性，比"不可编辑"严重；扫描件还要 OCR，错字直接污染 D3 数值抓取。
   - **`.txt`／`.md`：技术上四维全适配**（纯文本天然是行序列，正则全跑得通），排除是场景判断——同构批量材料诞生于"Word 模板套打、各单位填报"，产物天然是 docx/xlsx，没人拿 17 个 txt 交上来。写成"格式不支持"是错的，哪天真出现就该能跑。
   - **`.xlsx`：另立技能，不扩本技能**。Excel 是单元格网格不是段落流，D2 目标条体、D4 篇幅字数在表格里没有对应物；它该核的是表头对齐、列数一致、同列同量纲、跨表勾稽——另一套判据。让脚本"能打开 xlsx"只要十几行，但判据全数空转，属假绿灯，不做。
5. **D3 是线索不是结论**：同一数值重复可能是有意复述（摘要＋正文），脚本只负责把它摆出来。

## 七、待补维度（本轮刻意不做，遇到任务再加）

按"再做一次同类活时最想省的那一步"排序：

1. 修订／批注计数（交印前必须 0）；
2. 附件页数与版式（表宽、行高、字号——人工核对有现行口径，未脚本化）；
3. 引文逐字比对（要外部原文，属"联网"层，不进本脚本）；
4. 篇幅档位（按学院类型分档而非全集中位）；
5. 表格单元格内指标扫描；
6. **D2 第二信号（待实测）**：加"样式名含标题/Heading 的段落也计入目标条候选"以降漏报（2026-11-17 评测 E 输出准确性 4.4 点名"识别词有几率漏报"）——须先在真实材料上实测是否引入误报，未实测不动判据。

**加维度的规矩**：先在本目录 `CHANGELOG.md` 记一条"为什么加"，再加代码；一次只加一维，加完必须能在真实材料上复现旧结论不变。

## 九、验收（本版交付前实跑）

- 17 篇同构规划（2026-11-16，某改稿目录）：`doc` 输出 17 行，D1 命中 1 篇 2 处，D2 命中 7 篇；`cross` 输出篇幅 4,054–14,273、中位 9,133，篇内重复 28 处，跨篇金额类 1 组。
- 与人工结论对账：D2 的 7 篇里有 6 篇与人工"未用目标条体"名单一致（第 2 条局限所指那 1 篇漏判属已知）。
- 脚本在缺 `python-docx` 的解释器上按 `[E1]` 中止，不静默降级。
- 入口遇非 `.docx`（如混入 `.doc`／PDF）按 `[E3]` 整批中止：逐列出文件名＋各自处置指引，退出码 `2`，**不静默过滤、不出部分结论**（2026-11-16 实测混合输入与纯 docx 两路）。
- **自检锚（2026-11-17 新增）**：`python3 "$SKILL_DIR/scripts/self_test.py"` 在临时目录构造正反例样本，对偶数中位／D1 跳号／D2 未归一／E3/E4/E5/混合中止逐项断言，9 项全过退出码 0。**判据或错误码任何改动后必须重跑本脚本**——判据与自测两处不一致即发布阻断（回应评测"缺长期稳定的自动验证方式"）。
