# 古籍语料入库器（guji-yuliao）

**与 book-to-skill 的分工**：同一本"书→技能"上游，下游分叉——book-to-skill 提炼"作者想教我什么"（框架/原则，明言不保原文）；本技能保"原文到底写了什么"（逐字分册＋回目索引），服务于引用核对。纯方法论书只需前者；需要查原文引文的古籍才值得走本技能。

## 触发说法示例

用户说出下列类似说法时即使用本技能：

- 「把《三国演义》入库／做成语料」
- 「我要给《水浒传》建个原文库，方便引用核对」
- 「这本古籍是繁体的，帮我转成简体并按章回分册」
- 「从 Gutenberg 拉一部章回体小说建语料」
- 「把资治通鉴的 JSON 语料按卷入库，建成可检索的卷目库」
- 「我有一份编年体的 JSON，帮我按"纪"分组分册并建卷目索引」
- 「这份 JSON 的字段叫 juan / biaoti / zhengwen，怎么映射进来」

不该走本技能的说法：「帮我提炼这本书的方法论」（转 book-to-skill）、「把这篇文章存个档」（直接存档即可）。

## 安装自检（30 秒，动手前先做）

**先判定环境，再取底本。** `--t2s`（繁转简）需要 opencc，**其余功能全部零依赖**：

```
python -c "import opencc; print('opencc OK')"
```

- **打印 `opencc OK`** → 环境就绪，按下面「使用流程」走，第 3 步带 `--t2s`。
- **报 `ModuleNotFoundError: No module named 'opencc'`** → 两条路，**二选一，不要硬试**：
  1. **装上**：`pip install opencc-python-reimplemented`，装完重跑上面那条命令确认；
  2. **不装，走繁体路径**：第 3 步命令里**去掉 `--t2s`**，原文（繁体）照录入库。产物照样可检索、可核对、可建索引，只是字形保持繁体——**这是正式支持的路径，不是降级凑合**。

两种走法都会如实记进 `_manifest.json`：`t2s` 记 `true`/`false`，`opencc_version` 在未转换时为空串。日后对账能看出这批分册走的是哪条路。

## 两种源模式对照（先定模式，再走流程）

**第一步不是跑命令，是判源类型。** 选错脚本，后面参数全是白填。

| | **模式 A · 纯文本章回体** | **模式 B · JSON 记录列表** |
|---|---|---|
| **输入形态** | 单个 `.txt`（Gutenberg 等公版纯文本），正文里"第X回＋回目"独立成行 | 单个 `.json`，根节点**必须是数组**，一个元素＝一卷/一纪 |
| **脚本** | `scripts/build_split.py` | `scripts/build_json.py` |
| **前置要求** | python3；`--t2s` 另需 opencc | python3；`--t2s` 另需 opencc |
| **验收断言** | 回号连续 1..N（可有 ch000 楔子） | 卷号连续 1..N |
| **关键参数** | `--chapters N`（**探测也带上**）、`--prologue 楔子`、`--t2s`、`--source`、`--skip-head/--skip-tail`（非 Gutenberg 源裁头尾） | `--volume/--title/--content`（字段名映射）、`--title-override`、`--boilerplate`、`--strip-brackets`（默认开）、`--t2s` |
| **常见坑** | 回目行带前缀或全角冒号；多卷合订本混排；下载截断；非 Gutenberg 源残留版权页（用 `--skip-head/--skip-tail` 裁） | 源元数据不可信（period 空缺、记/纪形近）；卷号断档；卷首样板行须显式给正则 |
| **产出** | `<版本名>/ch000、ch001…`＋`<版本名>_回目索引.md`＋`<版本名>_manifest.json` | `<版本名>/ch001…`＋`<版本名>_注本/`＋`<版本名>_卷目索引.md`＋`<版本名>_manifest.json` |
| **预览** | `--probe` 真预览（不写盘） | `--probe` 真预览（不写盘，1.0.9 起与模式 A 一致） |

两条流程共用的三件事：**先 probe 核编号 → 断言失败零产物 → 入库后抽验首末单元。**

> 索引与回执的文件名带版本名——同一父目录下并存多个版本（毛本/金本、简体/繁体）互不覆盖。

## 使用流程

### 第 1 步 · 取底本
用户提供电子版文件路径或公版源（如 Gutenberg 编号）。**版权关**：只收公有领域文本；现代校注本有著作权，拒收或仅作私用并永不进发布版。

### 第 2 步 · 探测（必做）
```
python scripts/build_split.py --src <文件> --probe --chapters <期望回数>
```
**`--chapters` 探测时也要带上**：给了期望回数，脚本才会把"探测数 vs 期望"做成预警（exit 2）；不给也能探，但只剩"0 单元/回目不连续"这类硬错会拦（1.0.9 起同样退 2，不再静默通过）。
输出单元数、首末回目。**核对三件事**：①回数与期望一致（不一致先查是不是多卷本/选本——用"单回平均字数×回数 vs 文件大小"推算完整性；probe 支持 `--chapters N` 自动比对，不符即 stderr 预警并以 exit 2 退出）；②末回指纹对不对（金本水浒末回=惊恶梦、毛本三国=三分归一统——末回是版本系统的指纹）；③有无楔子/序言。

### 第 3 步 · 入库
```
python scripts/build_split.py --src <文件> --dst <技能>/references/<版本名>_简体 \
  --book <书名> --chapters <N> [--prologue 楔子] [--t2s] [--source 'Gutenberg #23863']
```
脚本内建坑位：UTF-8 BOM／数字写法多态（白圈○作零·数字连写·行首空格·大写壹贰叁…玖·拾佰·廿卅——"第廿一回""第陆回"式老书写法直接识别；ASCII 数字与全角数字亦认（"第12回""第１２回"）／章回行短前缀容忍（"是第一回"式）／古登堡许可证头尾切除／章回序列断言。产出：`<版本名>/ch000（楔子）+ch001…chNNN`＋`<版本名>_回目索引.md`＋`<版本名>_manifest.json`（**入库回执**：来源〔如实动态记录，`--source` 可覆写〕、底本 SHA-256 指纹、入库时间、转换参数——日后对版本、查"这批分册从哪个文件来的"全凭它）。

### 第 4 步 · 骨架三件套
按语料技能模板写 SKILL.md（工作流：回目索引定位→读分册核对→引用注明版本回目）＋LESSONS.md（复盘层，永不发布）。SKILL.md 必须写明**版本口径**（哪个本子、多少回、与其他通行本差异）。

### 第 5 步 · 双安全阀
引用核对抽验（首末回指纹＋随机一回）＋脱敏检查（语料本身无敏感信息，核对 SKILL.md 中的说明文字）。

### 第 6 步 · 回执双指纹（1.1.0 新增）
`_manifest.json` 里有两个指纹，**用途不同，不能混用**：

| 字段 | 算什么 | 用途 |
|---|---|---|
| `source_sha256` | **源文件字节**的 sha256 | 回答“同一本子还是那一份吗”（换下载源会变） |
| `content_sha256` | **实际入库正文**的 sha256 | 回答“手上的文本出自哪一步” |
| `content_stage` | 正文经历的处理阶段 | 如实记 `原文` / `繁转简` / `原文照录+剥夹注` 等 |

**为什么需要两个**：底本经 `--skip-head/--skip-tail` 切除、`--t2s` 转换、样板行剥离、【】夹注剥离之后，入库文本与源文件早已不是一回事。1.0.9 只记 `source_sha256`，等于**只能证明源、不能证明成品**——引用核对时会出现“指纹对得上，但文本不是那一份”的尴尬。1.1.0 起两段并存，核对时先比 `content_sha256`（它才对应你手上的文本），再比 `source_sha256`（它对应来源可追溯）。

## 端到端演练（实录）

新手第一次用，照这段真实命令＋真实输出走一遍即可（底本＝Gutenberg #23950 三国演义·毛本，1.8MB）。

**① 先故意探错，看预警长什么样**（期望 60 回，底本实为 120 回）：

```
$ python scripts/build_split.py --src pg23950.txt --probe --chapters 60
探测到 120 个单元（含楔子=无）
⚠️ 期望 60 回（不含楔子），探测到 120 单元、序列 [1, 2, 3, 4, 5, 6]...——请核对回目行是否带前缀或格式异常
（exit 2，零产物）
```

预警不是故障是设计：回数对不上，入库前就拦住你。**② 改对期望再探**（`--chapters 120`，exit 0），输出给出首末回目——末回"荐杜预老将献新谋，降孙皓三分归一统"，正是毛本指纹，版本系统拿对了。

**③ 入库**：

```
$ python scripts/build_split.py --src pg23950.txt --dst refs/毛本120回_简体 \
    --book 三国演义 --chapters 120 --t2s --source 'Project Gutenberg #23950（毛本）'
探测到 120 个单元（含楔子=无）
OK 入库 120 单元，总字数≈618919
首单元: 宴桃园豪杰三结义，斩黄巾英雄首立功
末单元: 荐杜预老将献新谋，降孙皓三分归一统
```

**④ 看产物**（输出目录旁自动带索引与回执）：

```
refs/
├── 毛本120回_简体_manifest.json   ← 入库回执（九字段，见下）
├── 毛本120回_简体_回目索引.md      ← 第001回　宴桃园豪杰三结义…（约4927字）逐行
└── 毛本120回_简体/
    ├── ch001.txt … ch120.txt   ← 120 个分册
```
（索引与回执的文件名带版本名——同父目录并存多个版本时互不覆盖。）

manifest 关键字段实录：`"source": "Project Gutenberg #23950（毛本）"`、`"source_sha256": "ed422e10…"`、`"ingested_at": "2026-10-20T07:13:23+08:00"`、`"t2s": true`、`"chapters": 120`、`"total_chars": 618919`。

**⑤ 抽验**：ch001.txt 开头是"第001回　宴桃园豪杰三结义，斩黄巾英雄首立功／词曰："，格式干净；但注意索引里"**餽**金珠"未转"馈"——opencc 词表盲区，如实保留（见报错表"繁转简后个别字未转"行），不手改。到这里入库即完成，后续骨架三件套见第 4 步。

## 常见报错与处置

**总原则：所有断言失败都是零产物退出——输出目录不会有半成品，修好参数直接重跑即可，无需清理。**"报错即停"不是缺陷而是设计：宁可不动手，也不写半个坏目录；所以每次失败后的正确动作只有一件事——按表修参数，重跑。

**退出码约定（两脚本一致）**：`0`=成功；`1`=环境/输入错误（文件不存在、缺依赖、JSON 结构不对、参数错）；`2`=数据预警（回目/卷号序列不匹配——零产物，核对底本后重跑）。脚本失败可按退出码分类处置，无需读 traceback 猜。

| 报错/信号 | 原因 | 处置 |
|---|---|---|
| `序列异常: [2,3]...` 入库中断（exit 2，零产物） | 实际探测回数与 `--chapters` 不符——多为回目行格式变体（前缀/全角冒号）或选本缺回 | 先 `--probe` 看首末回目；确认底本完整后修正期望值；若是格式变体，升级本脚本正则而非改样本 |
| `⚠️ 期望 N 回…探测到 M 单元`（probe，exit 2） | 探测数与期望不符的预警——静默少回在入库前就此暴露 | 同上；这是设计行为，不是故障 |
| `卷号不连续: ...`（build_json，exit 2，零产物） | JSON 源卷号断档/重复 | 核对源数据卷号；标题错漏用 `--title-override` 修。**注意 build_json 同样只收 1..N 连续卷号**——节选本在两个脚本里都不支持 |
| `序列从第 N 回起（不是第 1 回）——本工具仅支持从第 1 回起的完整底本…`（exit 2，零产物） | 底本从第 N 回起：**多半是下载被截断**（按《取底本检查清单》续传后重试）；若确为节选/续本，**本工具不支持**，且**请勿为凑 1 起而重编号**——回号重编会让语料回号与原书回号错位，引用核对立即失效。报错末尾附「命中行号示例」，可据此逐行核对 | 先续传重跑；确属节选本则换全本。**不要重编号**（1.1.0 已删掉 1.0.9 的两条假出路：「按回号补齐」与「改用 build_json.py 录入」——后者同样只收 1..N 连续卷号，是死路） |
| `⚠️ 严格回目判据未命中，已放宽到含半角空格`（stderr 告警） | 底本用半角空格分隔回目，或正文含「第X回 」被误判 | 放宽后若入库正常（exit 0）则无需处置；若随后报序列异常，**报错里的「命中行号示例」直接指出可疑行**（1.1.0 新增，C3 修复） |
| `--title-override 项格式错：'xxx'——应为 '卷号:新标题'`（build_json，exit 1） | override 项没写卷号，或写了空卷号 | 按 `卷号:新标题` 写；**新标题本身可含冒号**（如 `2:晋纪二十四:某事记`，1.1.0 起只切第一个冒号，不再抛 ValueError） |
| `缺 opencc：pip install opencc-python-reimplemented；或去掉 --t2s 以原文照录（繁体）入库`（exit 1） | 传了 `--t2s` 但未装 opencc | 二选一：按提示安装后重跑；或去掉 `--t2s` 跳过转换直接入库（保留繁体，回执 t2s=false 如实记录） |
| `找不到底本文件/源文件：...`（exit 1） | `--src` 路径错 | 用完整绝对路径；Windows 端注意反斜杠转义 |
| `期待记录列表型 JSON`（build_json，exit 1） | JSON 源不是记录数组（可能是嵌套 dict） | 检查源结构，必要时先做一层展开 |
| `⚠️ UTF-8 解码失败，已按 GB18030 读取` | 底本不是 UTF-8（常见于某些 Windows 导出/早期电子化文本） | 无需处置——已自动回退 GB18030 继续入库，回执 `source_encoding` 如实记录；若转换后乱码，说明连 GB18030 也不对，查底本真实编码 |
| 繁转简后个别字未转 | opencc 词表覆盖盲区 | 记入该技能 LESSONS，不逐字手改（语料以原文为准） |
| 非 Gutenberg 源：首尾残留版权页 | 该源无 `*** START OF` 标记，许可证自动切除失效 | 用 `--skip-head N` / `--skip-tail N` 裁掉（1.0.9 起真正可用，计数在许可证切除之后）；裁完再 probe 核对首末回 |

## 常见易犯的错误（反模式）

用本技能的人最容易栽在这五处——全部出自实战踩坑：

| 易犯错误 | 后果 | 正确做法 |
|---|---|---|
| 抓错版本系统 | 金本 70 回当通行本入库，回数对不上还以为是脚本坏了 | 先 probe＋末回指纹（金本=惊恶梦、毛本=三分归一统）；指纹不符＝拿错本子，立即停，换底本 |
| 拿源文件指纹当入库文本的凭据 | 经 skip 切除 / 繁转简 / 剥夹注后，源与成品已不同，只对 `source_sha256` 会得出“指纹一致”的假安心 | 核对入库文本比 `content_sha256`（1.1.0 起回执新增），源可追溯才比 `source_sha256` |
| 为凑“第 1 回起”重编回号 | 语料回号与原书回号错位，引用按原书回目查不到——本技能的价值被直接废掉 | 节选本本工具不支持（1.1.0 已删掉“按回号补齐”这条假出路），换全本 |
| 多卷合订本当单本 | 两册回目混进同一目录，索引错乱 | probe 时发现回数是预期的整数倍或两套回目开头，即是合订本——分卷分开入库 |
| 期望回数硬凑 | 选本缺回却传完整回数，序列断言失败 | `--chapters` 必须跟底本实况走：probe 探到几回就核几回，缺回先分清"选本如此"还是"下载截断" |
| 轻信 OCR 源元数据 | period 空缺/形近异文（记/纪）污染索引 | 标题必须过正文验证；错漏用 `--title-override` 手工修平，别直接信源字段 |
| 现代校注本当公版入库 | 发布版夹带受版权保护内容 | 入库前判版权：公版原文才可发布；校注本仅私用且永不进发布版 |

## 场景示例（两类）

### 示例一 · Gutenberg 章回体（水浒传·金本）

```
# 探测：确认 70 回＋无楔子，末回"惊恶梦"= 金本指纹
python scripts/build_split.py --src shuihu.txt --probe --chapters 70
# 入库：繁转简，71 个单元（楔子归 ch000）
python scripts/build_split.py --src shuihu.txt --dst refs/金本70回_简体 \
  --book 水浒传 --chapters 70 --prologue 楔子 --t2s
```
要点：末回指纹不符＝拿错版本系统，立即停。

**取底本检查清单**（下载完整性属使用者步骤，本工具不联网、只管入库）：

1. **续传**：`curl -C - -o 底本.txt <url>`——断点续传，别从头重来（重复下载易得到错版文件）
2. **大小对账**：拿到的文件大小与来源页标注的体积对照；差一个数量级＝多卷合订本或下错文件
3. **末回指纹**：读文件末尾，核对末回回目（毛本三国＝"降孙皓三分归一统"、金本水浒＝"惊恶梦"）——指纹不符＝拿错版本系统，立即停
4. **文件尾完整句**：末尾应是完整句号收束（而非断在半句）；UTF-8 文件末尾若见 `\xE4` 一类断字节＝下载被截断，重新续传
5. **入库前 probe**：以上四步过了，再用 `--probe --chapters N` 核回数与首末回目

### 示例二 · JSON 编年体（资治通鉴·四库本）

```
python scripts/build_json.py --src zizhi.json --dst refs/白文本_简体 \
  --book 资治通鉴 --volume volume --title period --content content \
  --strip-brackets --t2s --source 'gujilab/chinese-classical-corpus（CC0 派生）'
```
**JSON 字段怎么对上**（`build_json.py` 只认这三个键；键名可改，键必须存在）：

| JSON 里的键 | 语料里的位置 | 工具参数 | 要求 |
|---|---|---|---|
| `volume` | 分册文件名 `chNNN.txt`、索引里的"卷NNN" | `--volume <键名>` | 必须能 `int()`，且构成 **1..N 连续**（断档或重复 → exit 2，零产物） |
| `title` | 分册首行标题、索引标题 | `--title <键名>` | **可空**：空则从正文抽"Ｘ纪Ｎ"，抽不到记为 `卷N`；逐卷改题用 `--title-override` |
| `content` | 分册正文 | `--content <键名>` | 会被 `str()` 后原样写入；`--strip-brackets`（默认开）把 【】夹注剥到 `<版本名>_注本/` |

**源里多出来的键（作者、年代、卷次名等）本工具不读、也不校验**——元数据的正确性由你负责，工具只保证"卷号连续"。

要点：`--strip-brackets` 默认开启——【夹注】剥出另存注本（注不丢），要留在正文用 `--keep-brackets`；OCR 源元数据不可信——period 空缺/形近异文（记/纪）用 `--title-override '102:晋纪二十四,276:后唐纪五'` 手工修平；卷首样板行因本而异，须用 `--boilerplate` 显式给正则（不设默认，防静默删行）；卷号全局连续断言兜底。

## 常见问答（FAQ）

- **什么情况不用本技能？**——非章回体也非 JSON 记录列表的文本（如单篇长文）直接存档即可；现代有版权的校注本不收；只想提炼书的方法论去用 book-to-skill。
- **出错怎么办？**——先看上表"常见报错与处置"；所有断言失败都是**零产物退出**，不会写半个坏目录，放心重跑。
- **怎么中途收束？**——probe 之后随时可停：未入库=零残留；已入库想撤销，删产出目录即可（索引/manifest 同在目录旁，一起删）。
- **语料能直接发布吗？**——公版原文可以；但由它产出的技能包发布前仍要走脱敏 grep 与宿主规范（本工具只管"书→分册"，发布审查是另一道闸）。
- **Windows 能用吗？**——能。纯 Python 标准库＋可选 opencc，已在 Windows 10＋Python 3.13 实测（GBK 控制台报错零乱码、中文目录正常）。
