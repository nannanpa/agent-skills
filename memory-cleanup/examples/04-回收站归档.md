# 场景四：回收站归档（两段式）

**触发语**：「回收站归档」「清回收站」「回收站该收了」

**前提**：`trash_aged_days` 已设（默认 7，即归档区停留 7 天）；用户在场。

## 执行要点

1. **读阈值 → 三行报告**，确认归档天数（默认 `7`，即归档区停留 7 天；这是受控后悔期，回收站侧时长不测量）。
2. **搬移**：`~/.Trash` 顶层项（除 `.DS_Store`）`mv` 进 `~/.Trash.aged/<今天日期>/`。**搬移是可回退的**，先做。
3. **列出超龄**：`find ~/.Trash.aged -maxdepth 1 -type d -name "????-??-??" -mtime +N`，**只列出，不删**。
4. **报备**：对每一项报路径与体积（`du -sh`），并说清判据——"该文件夹在归档区已停 7 天以上，达到受控后悔期（N=7 天）；回收站侧停留时长本技能未记录，不作为判据"。
5. **用户确认后逐个删**：只删上一步列出的、只删日期命名文件夹。用户不确认 → 本轮只报不删。
6. **报告**：回收站剩余项数与体积、本次搬入项数、归档区总占用、本次删除项数、失败项。

## 报告长什么样（示例数值为示意）

```
本次按以下阈值执行：swap 警戒 10240MB ｜ 微信上限 20 ｜ 回收站 7+7 天 ｜ agent 路径未设（已跳过）。
…

回收站：搬入 23 项（约 1.4GB）→ ~/.Trash.aged/2026-11-16/
归档区：现有 4 个日期文件夹，合计 6.2GB
超龄待删（归档区已满 7 天）：
  ~/.Trash.aged/2026-10-18   1.9GB
  ~/.Trash.aged/2026-10-25   0.7GB
删除：2 项已删（2.6GB），用户已确认；失败 0
回收站剩余：0 项
```

## 验收对比

| 项 | 要求 |
|---|---|
| 后悔期是否保住 | 从回收站直接进归档区（不是直接删）；归档区天数与 config 的 `trash_aged_days` 一致，该 N 天即受控后悔期。回收站侧时长不测量，故不按 2N 验收 |
| 删的是谁 | 只删 `~/.Trash.aged` 下、`????-??-??` 命名的文件夹；**绝不删 `~/.Trash` 里的任何东西** |
| 删前是否报备 | 路径 + 体积 + "已满多少天"，三项齐了才问确认 |
| 是否碰外接卷 | 不碰；外接卷的回收站按卷单独处理 |
| `.DS_Store` | 不动 |
| 失败项 | 如实报路径与原因，不重试、不 `sudo` 硬删 |

**判过标准一句话**：用户能从报告里指出**每一个被永久删除的文件夹是什么时候进来的**。做不到这一点，说明判据没用"日期文件夹名"——那这套流程就已经不是两段式了。

## 为什么这一步要分两次触碰

搬移一次、删除一次，中间隔着"用户看清单"。合并成一次（"顺手把超龄的也删了"）就回到了"一次操作、零后悔期"——那正是直接清空废纸篓的做法。**分开的唯一目的，是把不可逆动作推迟到用户看过清单之后。**

## 失败处置

`mv` 失败（被占用、权限不足、目标不存在）→ 该项留在原位、报路径；`rm -rf` 失败 → 报路径与错误、留在归档区等下一轮。**`EXDEV`（跨卷）最常见**——外接卷上的东西不要并进本流程。
