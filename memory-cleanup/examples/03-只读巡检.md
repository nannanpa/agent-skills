# 场景三：只读巡检（只看不动）

**触发语**：「内存巡检」「看看内存」「swap 怎么样了」「先别动，报个数」

**前提**：用户只想了解状况，或怀疑有问题但还没决定要不要清理。

## 执行要点

1. **读阈值 → 三行报告**。
2. **只做第五节（只读巡检）**，**不进入第六节**：不检查确认、不执行 `pkill`、不搬回收站、不改 config。
3. **每一项都带判据与结论**，不要只丢数字：数字没有判据，用户没法判断要不要管。
4. **给判断不给动作**：可以说"swap 超线了，建议择机重启"，但不替用户执行，也不反复劝。
5. **收尾一句**："需要动手时说'内存清理'。"

## 报告长什么样（示例数值为示意）

```
本次按以下阈值执行：swap 警戒 10240MB ｜ 微信上限 20 ｜ 回收站归档区 7 天（受控后悔期，回收站侧不计入） ｜ agent 路径 /Users/<you>/.agent-browser/browsers。
可调项：…
内存档位：本机 16GB，swap 线建议 10240MB，与当前值一致。

只读巡检（未做任何更改）：
· 内存空闲 21%——不设绝对线，仅作趋势观察
· swap 已用 11264MB / 10240MB 警戒线 → **超线**，内存压力已穿透到磁盘
· agent 实例 0 → 无残留
· 微信类进程 23 > 上限 20 → 偏高

判断：swap 超线是唯一需要处理的项，且**清零只能靠重启**；微信类进程可退出重开回收一部分。
本轮未终止任何进程、未改动任何文件。
```

## 验收对比

| 项 | 要求 |
|---|---|
| 是否动了系统 | **零动作**：无 `pkill`、无 `mv`、无写 config、无删文件 |
| 四项是否齐 | 空闲 %、swap、实例数、微信类进程，缺一项即不完整 |
| 是否带判据 | 每项都要有"怎么判"，不能只是数字罗列 |
| 是否越界给动作 | 只读场景下不得自行执行清理 |

**只读巡检的价值**：它是唯一可以随时跑、零风险的动作。把它做成默认动作，用户才敢问"现在什么情况"，而不是只在出事时才用一次重手。

## 常见误用

- **把"只读"做成"什么都没做"**：只读不等于不给结论。采了数却不说"超没超线"，等于把判断塞回给用户。
- **顺手清一下**：只读场景里最忌讳"反正看见了就杀掉"。用户没说动手，就是不动手——这条守住了，技能才敢默认只读。
