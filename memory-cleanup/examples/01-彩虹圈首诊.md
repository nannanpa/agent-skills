# 场景一：彩虹圈首诊（首次部署后的第一次跑）

**触发语**：「内存清理」「彩虹圈了」「内存不够了，看看」

**前提**：技能刚装好，`config.json` 还没建或还是默认值。

## 执行要点

1. **先读阈值，把三行报告打出来**（`SKILL.md` 第四节）。此时 `agent_browser_path` 是空 → 报告第一行会写"agent 路径未设（已跳过）"。
2. **只读巡检**（第五节）：内存空闲 %、swap 已用、agent 实例数、微信类进程数，四项一次采全。
3. **检测浏览器目录**（6.1）：命中则给一句建议"检测到 `~/.agent-browser/browsers`，建议填入 config"。
4. **问一句**："现在有上传/浏览任务在跑吗？"——用户答"没有"才进下一步。
5. **基线 → 清理 → 验证**（6.2）：先存三个基线数，再按路径终止，5 秒后仍有残留才补 `-9`，最后再采一次。
6. **报告**：实例数、空闲 %、swap MB 三组前后对比 + 建议（swap 超线则建议择机重启）。

## 报告长什么样（示例数值为示意，非判据）

```
本次按以下阈值执行：swap 警戒 10240MB ｜ 微信上限 20 ｜ 回收站归档区 7 天（受控后悔期，回收站侧不计入） ｜ agent 路径未设（已跳过）。
可调项：…
内存档位：本机 16GB，swap 线建议 10240MB，与当前值一致。
提示：检测到浏览器目录 ~/.agent-browser/browsers，建议填入 config 的 agent_browser_path。

巡检：实例 12 ｜ 空闲 12% ｜ swap 已用 6820MB（未超 10240）｜ 微信类进程 22（超上限 20）
清理：已终止 agent 浏览器实例；5 秒后实例 12 → 0
对比：实例 12→0 ｜ 空闲 12%→34% ｜ swap 6820→6810MB
建议：swap 未超线，无需重启；微信类进程 22 个，建议退出重开（我不替你动手）。
```

## 验收对比

| 项 | 基线 | 收尾 | 判过标准 |
|---|---|---|---|
| agent 实例数 | 12 | 0 | **必须归零**（计数口径含 crashpad，与清理口径同源） |
| 内存空闲 % | 12% | 34% | 应上升；不上升也不算失败，但要给出"实例已清、内存未回"的解释 |
| swap 已用 | 6820MB | 6810MB | **允许不降**——swap 只能靠重启清零（FAQ Q2），不降不是失败 |
| 报告三行 | — | 齐 | 缺任一行视为本轮未完成 |

**本轮不算成功的三种情形**：实例数没归零（有残余未处理）、报告只有一次读数（无基线，不可证伪）、用户答"有任务在跑"仍执行了清理（越过了确认关）。

## 量级参照（实测案例，去本机绑定）

16GB 统一内存机型，2026-10 的一次实测。25+ 个 Chromium 实例把内存吃到 swap 已用 13.8GB、swap 文件涨到 15 片，系统出现彩虹圈。终止自动化浏览器残留后，内存空闲 31%→55%。

**这个量级说明**：残留清理的收益不在"省几百 MB"，而在"别让实例数滚到两位数"——单个实例数百 MB，十几二十个就是一台机器的可用内存。
