# pdf-to-md：PDF → 规整 Markdown

专治**中文公文/红头文件类 PDF**：把碎行、页码残留、粘连的标题与字段标签规整成段落连贯的 Markdown。

> **定位**：marker、docling、pymupdf4llm 等重型工具比的是版面还原能力；本技能不跟它们比——只做"从碎行到连贯段落"的最后一公里，规则清单专为中文公文结构设计（`一、` `（一）` `1.` 段首体系、"责任单位：/联系人："字段标签），并保持零 Python 依赖（仅 pypdf）、全规则可读可改。

## 何时用 / 何时不用

- ✅ PDF 带文字层（OCR 产物、原生电子 PDF）。**不确定就先跑第 1 步，看提取量**。
- ✅ 纯扫描件——**走第 0 步的 OCR 分支**（macOS 自带 Vision，零安装；见下）。
- ❌ 需要保留表格线、图片、版式——本技能只产纯文本流（Markdown 表格会保留，但不还原单元格边框）。
- ❌ 非 macOS 的扫描件——本技能自带的 OCR 脚本是 Swift 版；其他系统请用本机可用的 OCR 引擎，并保证输出仍是逐行文本。

## 管道（三步）

依赖：Python 3.8+ 和 `pypdf`。**安装 pypdf 请装进隔离虚拟环境，不要全局安装**（避免污染系统环境）：

```bash
python3 -m venv .venv && .venv/bin/pip install pypdf   # 或使用平台托管 venv
```

### 第 0 步 · 分流：这是文字层还是扫描件？（**先做这一步，别跳**）

```bash
python3 <本skill目录>/scripts/pdf_extract.py 输入.pdf 中间产物.md
```

脚本会逐页提取并在页间插 `<!-- 第 N 页 -->` 页标记。**看提取量**：

- 每页有正常文字量 → 跳到第 2 步规整；
- 每页几十字、或正文为空 → **纯扫描件**，走下面的 **OCR 分支**。

> **判据也可以更硬**（2026-10-30 实测）：扫描件的 PDF 里 `/Font` 与 `/ToUnicode` 出现次数为 **0**，正文全是 `/Image` 对象；文字型 PDF 则有字体表。两条判据一致时以提取量为准。

### OCR 分支（纯扫描件专用，macOS）

**不要装 PaddleOCR/Tesseract**——常装不上，还要拉依赖。macOS 自带 **PDFKit + Vision**，`/usr/bin/swift` 直接能跑，**零安装、零网络、零 Python 依赖**，能认简体中文。

**一步到位**（推荐，1.2.0 新增）：

```bash
swift <本skill目录>/scripts/pdf_ocr.swift 输入.pdf 中间产物.md
```

一条命令走完三步：**PDF → 逐页渲染 PNG → Vision 离线 OCR → 带页标记的中间产物**。

- 产物格式与 `pdf_extract.py` **完全一致**（`# <文件名> 提取文本` + `<!-- 第 N 页 -->`），**可直接喂给 `clean_md.py`**；
- 渲染用 macOS 自带 PDFKit，**不需要 PyMuPDF/fitz**（实测当前环境 fitz 与 pypdf 都没装，这条链路照样跑通）；
- 低置信度行自动加 `〔OCR待核〕` 标记（阈值默认 0.5，`--low-conf 0` 可关闭）；
- **传真件页眉/页脚自动识别**：行落在页顶/页底 7% 且多页重复 → 标 `〔页眉页脚〕`（**只标不删**，删不删由人决定）。

**分步做**（需要中间 PNG、或已有图片目录时）：

```bash
# ① 只渲染 PNG（每页一张）
swift <本skill目录>/scripts/pdf_ocr.swift 输入.pdf pages/ --render-only --png-dir pages

# ② 批量 OCR（图片目录 → 同名 .txt，按行序）
swift <本skill目录>/scripts/ocr_vision.swift pages

# ③ 疑难单行定位：带置信度与坐标输出，用于回图核字
swift <本skill目录>/scripts/pdf_ocr.swift 输入.pdf /tmp/out.md --page 3 --coords
```

> **坐标用法**：`--coords` 输出 `置信度 x y 宽 高`，x/y 为归一化值且**原点在左下角**；按 y 排序即行序，按 x 排序即同行左右序。行中心 = y + **高**/2。

**OCR 阶段的三条规则**（`pdf_ocr.swift`）：

| 规则 | 判据 | 处置 |
|---|---|---|
| **逐行排序** | y 降序（Vision 原点在左下，故 y 大的在上），同行按 x 升序 | 直接成行 |
| **低置信度打标** | 行置信度 < 阈值（默认 0.5，`--low-conf` 可调，0 表示不标） | 行尾加 `〔OCR待核〕`，**只标不删** |
| **页眉/页脚识别** | 行中心落在页顶/页底 **7%** 之内，且**不止一页**在该区域有行 | 行尾加 `〔页眉页脚〕`，**只标不删** |

> **为什么页眉判据是"几何 + 多页"而不是"跨页文本相同"**：传真页眉是位图，同一传真头每页 OCR 结果可能有细微差异（实测同一页眉出现 `628811662227` 与 `628811662221` 两种结果），纯文本匹配会漏。几何判据稳定，且"多页重复"这一条能保证**不误伤第 1 页顶部的发文机关标志**（实测"国务院学位委员会文件"在 y≈0.78，远离页顶 7%）。

**OCR 输出必须逐处回图校验**——机器读字是起点，不是结论。2026-10-30 在一份 2011 年传真件上实测，Vision 把"2012年**7**月"读成"2012年**1**月"（试点期起止的关键事实）、把"**教学**要求"读成"**数学**要求"，另有十余处形近误识（儒求/带求→需求、脈属→隶属、授子→授予、硬士→硕士、姿员会→委员会、备菜→备案…）。凡涉及**日期、数字、机构名、人名**的，一律回图确认。

OCR 结果（`pdf_ocr.swift` 已自动带上 `<!-- 第 N 页 -->` 页标记）进入第 2 步规整。若你走的是分步路线、手工 OCR 出的 txt，需要自己补上页标记再进第 2 步。

### 第 2 步：规整

```bash
python3 <本skill目录>/scripts/clean_md.py 中间产物.md 最终文件.md "文档标题（提取文本·规整版）"
```

可选开关：`--para-patterns "正则|正则"`（追加自定义段首模式）、`--no-punct`（关标点归一）、`--no-noise`（关噪声打标）、`--no-redhead`（关红头扩展包）。

**退出码约定**：`0` 成功 ／ `1` 参数错或文件错（都带「💡 怎么办」提示）／ `2` 输入里没有可规整的内容。2 专门留给「没东西可整」，参数错不混进来——调用方可用「非 0 且非 2 = 用法错」做判断。

### 第 3 步 · 比对核对（规则改过之后必做）

```bash
python3 <本skill目录>/scripts/diff_versions.py 旧版.md 新版.md
```

逐段对齐，输出**新增段／删除段／改写段（带相似度）**，供人工逐条核对"到底哪些字变了"。相似度低于阈值的配对不硬凑——宁可报"新增+删除"，也不谎称"改写"。加 `--json` 可程序化消费。

## 规整规则清单（clean_md.py 已内置）

按实战迭代出的规则，遇到新形态文档可往里补：

1. **页码残留清除**：`-3-`、`—15`、孤行数字等整行匹配即删
2. **强制断行合并**：PDF 每行末尾的硬回车拼接成完整段落（跨页断句靠页标记分块后自然接上）
3. **段首识别重排**：以下模式开头的行强制另起一段——
   - 节标题：`一、` `二、` …
   - 条目：`（一）` `(二)`（半角全角都认）`1.` `1、`
   - 字段标签：`联系人` `责任单位` `整顿重点` `查处重点` `组长/副组长/组员` `附件` `送：` 等
   - 红头扩展包（1.2.0）：`国务院学位委员会文件`、`学位〔…〕号`、`^关于…`（**要求整行无句读**——裸「关于」会把正文里"关于这个问题…"切成独立段，那是误拆）、`^有关省`、`^[〇一二三四五六七八九十]{4}年`、`^抄送：`、`^为做好`、`^如下意见`
4. **标题粘连拆分**：两条并行规则——
   - **泛化起段**：`。` `；` `！` `？` 之后紧跟 `一、`~`十、` 编号时起新段（不依赖写死标题词表）
   - **已知标题词独立成行**：`一、总体要求` 等词表命中时标题单独一行、正文随段
   - `（简称…）` 不误断
5. **纯节标题短行独立成段**：`一、` + 短标题 + 整行无句读 的行自成一段（泛化判定，不依赖写死词表）
6. **字段标签断行**：段中粘连的`责任单位：``联系人：``整顿重点：`等标签前强制换行
7. **表格整块保护**（1.2.0）：连续的 `|` 开头行视为**一个不可拆单元**，行间不留空行（留空行 Markdown 表格语法就断了）。此前 5 列表格会被并成一行
8. **标点归一**（1.2.0）：半角句读 `, ; : ! ? ( )` 任一侧邻接**汉字或中文标点**即转全角；**两侧同为数字或拉丁字母时不转**（保护 `010-66097148`、`92-111`、`3.14`、`SBTI (Test)`）。中文标点（`""''《》（）` 等）**算 CJK 侧**——这是 1.1.0 验收遗留项的收紧口径。**成对的英文直引号转中文引号**（`"…"` → `“…”`，行内第 1、3、5… 个为左引号）；数量为奇数时最后一个保持原样——不成对就不猜开闭；英文单引号 `'` 不动（缩写误伤风险大于收益）
9. **噪声打标**（1.2.0）：疑似 OCR 噪声串**原地加〔噪声待核〕标记，不删**。判据：字母数字交错的短串（如 `L1ti`）、连续 7 位以上纯数字（如 `61202611016`）。不打标含连字符的数字串（`010-66097148`）与被汉字隔开的短数字段（`2026年10月16日`）。**打标不可逆、删字才不可逆**——所以只标不删。整行规则与行内规则**互斥**：同一串只带一个〔噪声待核〕，不出现〔噪声待核〕〔噪声待核〕
10. **报头区三段分离**（1.2.0）：红头文件报头区最常见的粘连形态是「标题 + 受文机关 + 正文首句」挤成一行。拆成三段——
   - **标题与受文机关分离**：`……的通知` 紧跟机关列举词（`各省` `各有关` `有关各` 等）→ 在此断开
   - **受文机关与正文分离**：机关名列表（逗号/顿号分隔）以冒号收尾 → 冒号后断开，正文另起一段
   - **冒号后是数字则不动**：`政策咨询电话:010-66097148` 属字段标签不是受文机关，拆开会把号码甩到下一段（实测踩过）
11. **版本比对**（1.2.0 新工具）：`diff_versions.py` 逐段对齐两版，输出新增/删除/改写三类差异，供人工核对

**扩展方法**：改 `clean_md.py` 里的 `PARA`（段首模式）和字段标签列表，加新关键词即可；**不改脚本**用 `--para-patterns "正则|正则"` 追加段首模式。通用公文骨架已覆盖，定制词（如"部内发送""工作提示"）按文档类型增删。

## 输出约定

- 最终文件名建议：`原文件名.md` 或 `原文件名（提取文本·规整版）.md`，放原 PDF 同目录
- 规整后必须**抽读头、中、尾各一段**确认：无页码残留、段落连贯、标题独立成行、表格未被打散
- OCR 错别字（如"领城/问瓶"）**不要自动改**——只列可疑词清单交用户核对，避免误改正文。噪声打标同理：**标出待核，不替用户决定删不删**

## 常见问题（FAQ）

- **PDF 明明有字，提取出来却是空的／只有几行**：看第 1 步输出的"每页平均字符数"。**少于 100 基本就是纯扫描件**——直接走 OCR 分支（`pdf_ocr.swift`），别在规整上耗时间。
- **OCR 出来错字很多**：这是常态，不是故障。Vision 对形近字与数字不可靠（实测"2012年7月"读成"2012年1月"、"教学要求"读成"数学要求"）。**凡涉及日期、数字、机构名、人名，一律回图核**——用 `--page N --coords` 定位到具体行。标了`〔OCR待核〕`的行就是回图的优先清单。
- **表格被拆散／Markdown 表格语法失效**：表格语法要求**块内不能有空行**，空行一插就断。规整脚本已做整块保护；若仍散，先看输入里是不是本来就有空行把表格行隔开了。
- **页码／页眉没清干净**：纯页码（`-3-`、`—15`）会自动删；**带文字的页眉**（如传真件每页的"发件时间＋发件方＋号码"）**只能标不能删**——`pdf_ocr.swift` 会打`〔页眉页脚〕`，删不删由你决定。
- **处理到一半发现这份文档不适合，早停**：**第 0 步分流就能判断**——每页有正常文字量就继续，只有几十字才进 OCR 分支，别提前渲染一堆图。规整阶段若段落结构实在还原不了，用 `--no-punct` / `--no-noise` / `--no-redhead` 关掉相应规则重跑，比逐处手改快。
- **什么时候不要用这个技能**：要保留表格线／图片／版式（只产纯文本流）；非 macOS 且本机无 OCR 引擎（纯扫描件做不了）；文档是跨栏／双栏排版（行序会交错，本技能不做栏序还原）。
- **两版内容对不上，想知道到底改了哪几处**：`diff_versions.py` 逐段对齐，输出**新增／删除／改写**三类差异，相似度低于阈值的宁报"新增+删除"也不谎称"改写"。

## 已知边界

- **OCR 错别字不自动改**（见"输出约定"），规整版可能残留"领城/问瓶"类错误；**OCR 读错的数字尤其危险**（"2012年1月" vs "2012年7月"），涉及日期与编号处必须回图核。
- **非 macOS 无自带 OCR 脚本**：`ocr_vision.swift` 依赖 Vision 框架；Windows/Linux 需另找 OCR 引擎，本技能不含。
- **跨栏/双栏排版**的 PDF 提取后行序可能交错，本 skill 不做栏序还原，规整前请先目检第 1 步产物。
- **表格只保结构不保边框**：Markdown 表格保留行列内容，不还原合并单元格与框线。
- **报头区粘连已由红头扩展包覆盖常见形态**（发文机关标志／发文字号／标题／受文机关／落款日期／抄送，另含标题与受文机关、受文机关与正文的分离）；但各校发文机关标志写法不一，本校特殊写法用 `--para-patterns` 追加即可，不必改脚本。
- **报头区拆分的边界**：受文机关的判定要求「机关名列表 + 冒号收尾 + 冒号后不是数字」。若贵单位公文用「各有关单位（名单）」而非冒号收尾，则受文机关不会独立成段——把机关名分隔符补进 `--para-patterns` 比改脚本更稳。
