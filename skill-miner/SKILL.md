# 技能孵化器（skill-miner）

把"手艺人的隐性经验"显性化：用户在日常对话中积累的流程经验、公文套路、排查手法，大多随会话结束而流失。本技能负责**回看任务历史、发现可复用模式、产出候选提案**——它是 skill-creator 类技能的上游：先回答"什么值得建"，再交给"怎么建"。

**给非技术用户的承诺**：你不需要懂任何术语。一句话（如"帮我看看咱们的任务里能不能提炼 skill"）即可触发，全程只需做选择题。

## 使用时机

- 用户明确询问："我让你帮我完成的任务里，是否能够提炼一个或多个 skill？"
- 用户表达固化意愿："这个流程以后还要用""能不能把这套做法存下来"。
- 定期回顾（可选）：用户要求盘点近期能力产出时。

**不要主动滥用**：没有用户发起或明确要求时，本技能不自动运行——提炼是提案，不是打扫。

**触发说法示例**（下列说法出现即启动）：

- 「我让你帮我完成的任务里，能不能提炼一个或多个 skill？」
- 「帮我看看最近的工作里有什么值得做成技能的」
- 「这套做法以后还要用，能不能固化下来？」
- 「盘点一下近期能力产出」

**降级处理**：若本技能文件不可读或宿主未正确加载，用户可直接说"按 skill-miner 的四步流程手动走一遍"——AI 依据本 SKILL.md 的工作流照做即可，不依赖额外机制。

### 什么情况不用

- **一次性任务**：不会再发生的操作（装一次软件、查一次资料）不构成候选；
- **纯灵感无步骤**：没有操作顺序与决策点的点子，无法固化成流程；
- **已有现成技能**：目标宿主技能市场已有同类的，建议直接安装而非自建。

### 可选进阶 · 定期自动盘点（用户自建）

技能机制不含"装后自动运行"。若你希望定期盘点，请**自行创建**一个定时任务（自动化/计划任务），提示词参考：

> 调用 skill-miner，扫描最近一周的任务记录，若有满足判据的候选按一页纸提案输出；没有就说"本周无可孵化候选"，不做多余分析。

建议频率：**每周一次**足够（skill 从任务里长出来是周级节奏，天天扫只会产出空转报告和 token 账单）。随时可停，停了不丢任何东西——提案文件都在。

## 工作流程（五步）

### 第 0 步 · 圈定素材

**动作 0-1 · 先读历史提案（1.1.0 新增，防重复提案）**：打开 `<技能目录>/skills-candidates/`，把旧提案逐份读成三张名单——**①已建**（技能名＋日期）**②已否决**（日期＋理由）**③缓议**（观察判据＋到期日）。本轮只提不在这三张名单里的候选。

> 为什么放在最前面：提案消耗的是用户的注意力。不查重就提问，等于让用户替我做本该我做的查重——而且他会以为我忘了。

**动作 0-2 · 按"独立场合"数反复（1.1.0 新增，防频次误判）**：数"这类需求发生过几次"，**不数文件数**。同一目录下堆十个同类文件＝**一次**长往来；跨日期、跨对象、跨目录各算一次。频次只看得见"写了多少"，看不见"发生在几次"。

回看**本会话上下文**与**可访问的任务记录/工作笔记/记忆文件**（各宿主不同：会话历史、memory 目录、笔记库均可）。只看近期的、实际发生过的任务——不推测、不虚构。

**除成品任务外，优先检查同一件事被反复执行、试错、回退的段落**（1.0.4 补）。反复本身就是缺护栏的信号：护栏类小工具（校验脚本、批处理补丁、防呆检查单、错误处置规则）多埋在这些"折腾过程"里——很多技能正是从任务执行中的临时补丁长出来的。注意区分两种情况：护栏**已固化**（补丁已打进脚本/纪律已写成文件）＝已排除，不重复提案；护栏**只在对话里口头存在**＝优先提案对象。

### 第 1 步 · 复盘扫描（发现模式）

**第零筛（先筛再判，1.1.0 新增）**：命中"护栏已固化"的直接排除（补丁已打进脚本、纪律已写成文件、检查单已在跑）——固化＝问题已解决，重复提案只是重造。**过筛的才进三判据**。

在过筛的素材中，筛同时满足三条判据的模式：

1. **场景重发**——同一类需求在**两个以上独立场合**出现过（不同日期、不同对象或不同目录各算一个场合；**同一目录下十个文件仍只算一次场合**），或用户明言"以后还会这么干"；
2. **有步骤、有决策点**——存在可描述的操作顺序和判断分支，不是一次性灵感；
3. **有模板/清单/规则产出**——曾沉淀出可复用的表格、清单、文案骨架、检查规则。

三条全中才是候选；只中一两条，明确说"不建议"，并说明差在哪。

### 第 2 步 · 候选提案（只提案，不建）

每个候选输出**一页纸提案**，格式固定（直接复制填写）：

```
## 候选技能：<名称>
- 状态：待裁 ／ 已建（技能名＋日期）／ 已否决（日期＋理由）／ 缓议（观察判据＋到期日）——**四选一，必填**
- 证据：本会话/记录中出现的任务（引用具体事项，1-3 条；**标明是几个独立场合**）
- 解决什么：一句话说清它替用户省掉什么重复劳动
- 覆盖范围：核心场景 1 句；边界外场景 1 句（诚实边界）
- 市场核查：目标技能市场／同类平台是否已有？有→写明差异；无→写"未命中"；没查→写"未查"。**不许留空**
- 选址结论：本地脚本够 / 需要外部连接 / 仅说明壳——为什么
- 敏感信息检查：需要脱敏的内容清单（人名/机构/内部数据）；**确无时写"无（理由：…）"，不许只写一个“无”字**
- 产物：`<技能目录>/skills-candidates/<YYYY-MM-DD>-<主题>-提案.md`（**提案与技能同住**，不散落工作区；**同日多份必须带主题名，否则撞名**；工作区另存仅在用户要求时）
```

**铁律：只提案，不直接建技能。** 提案权在本技能，批准权在用户——用户明确说"建"才进入第 3 步。一页纸都没有的候选不许口头带过。

### 第 3 步 · 批准后建档

用户批准后，按目标宿主的技能规范建档（通用最小集）：

```
<skill-name>/
├── SKILL.md        # 必需：frontmatter（name/description）＋工作流
├── references/     # 可选：模板、清单、分册语料
├── scripts/        # 可选：可执行脚本（确有自动化价值才写）
└── LESSONS.md      # 复盘层：踩坑与口径修正——永不进发布版
```

- 若宿主已有 skill-creator 类技能，**交给它完成建档**，本技能只交付提案与骨架要点，不重复造轮子；
- **建档后必须回填索引（1.1.0 新增）**：在该宿主的沉淀索引（如总目录 INDEX、技能清单）里补一行——名称／路径／用途／何时用。**不登记等于没沉淀**：建了技能却查不到，下次扫描照样找不到，等于白建；
- SKILL.md 写法保持**宿主中立**：不写死任何一家的安装路径；需要提路径时按宿主各自约定注明。

### 第 4 步 · 双安全阀（每次必过）

1. **选址阀**：建之前再答一遍——"本地脚本够不够？要不要外连？值不值套壳？"一次性任务不建；层放错=维护翻倍。
2. **脱敏阀**：拟对外分享的版本，逐项 grep 人名、机构名、内部数据、密钥口令；"私用版"与"发布版"分目录；复盘层（LESSONS）永不进发布版。

### 第 5 步 · 收尾自查（1.1.0 新增：不留「待回流」）

每次运行结束前答三问，答完才收工：

1. **本次产生"待回流经验"了吗？**（发现流程漏洞、写法没规定、口径要改）→ 有则**当场改 SKILL.md 或写进 LESSONS.md**，标日期。**禁止只写“待回流”三个字就收起**——实证：一条"待回流"在文件里躺了九天没人动。
2. **提案的“状态”字段都填了吗？**（待裁／已建／已否决／缓议）没填的下次扫描无法判断该不该重提。
3. **本次提案里有没有真实人名、内部数据、本机绝对路径？**有则按脱敏阀清理后再交。

## 偏差处置预案

| 偏差症状 | 纠偏句式（对 agent 说） | 恢复动作 |
|---|---|---|
| 越权直建：没出提案就动手建了技能目录 | "退回去——先出一页纸提案，我批了再建" | 删除未批准的目录，回到第 2 步 |
| 判据放水：**最终提案数 > 2**（命中数不限，但每个命中都得写明“提／不提”与理由） | "判据收紧——三条全中的才算，逐一说明证据" | 逐候选复验三判据＋第零筛，砍到 0–2 个 |
| 无中生有：提案引用的任务在记录里查无实据 | "只看实际发生过的任务，虚构的剔除" | 重跑第 0 步圈定素材，只保留可引用条目 |
| 重复提案：提了一个已建过／已否决／正在缓议的技能 | "先查历史提案——三张名单里有它" | 回到动作 0-1 读旧提案，当轮撤回并记档 |
| 频次误判：把“一次密集往来”当成“长期高频”（例：同一目录十几封函） | "按独立场合数重算，不是数文件数" | 按日期×目录重新归并场合，再排优先级 |
| 过程废料当噪音：把"反复试错/回退"的段落跳过没读 | "折腾段落优先精读——反复=缺护栏的信号" | 回到第 0 步补扫过程段落；护栏已固化＝排除，未固化＝按三判据走提案 |
| 敏感夹带：提案里出现人名/机构/内部数据 | "脱敏后再给我——提案里只留职务与流程，不留具体的人和事" | 按脱敏阀逐项 grep 清理后重新提交 |
| 用户否决后反复推销 | "否了就是否了，记档不再提" | 提案文件标注"用户否决（日期）"，本轮不再复述 |

**技术面异常**（本技能为纯文档实现，无 try-catch，遇技术故障按下列处置）：

| 症状 | 处置 |
|---|---|
| 素材源读不了（路径不存在/权限不足/编码错） | 向用户说明原因，请其给出正确路径或直接粘贴文本，不要跳过或编造素材 |
| 提案文件写入失败 | 把提案全文直接输出在对话里交付，写入只是留档手段，不阻塞提案本身 |
| 素材太多扫不完 | 主动请用户圈定范围（时间窗/项目），分批扫——不静默抽样假装全扫 |

## 场景示例（三类＋一反例）

### 示例一 · 文档/材料写作类

用户在同一周内让 AI 起草过两份同类材料，第二次时说"跟上次那个格式一样"。

- **扫描**：场景重发✓（两份同类材料）；步骤决策点✓（取素材→定口径→套骨架→核对引语）；模板清单✓（已沉淀出结构骨架与用语对照表）→ **构成候选**；
- **提案要点**：候选名"同类材料写作助手"；选址=本地模板库够、无需外连；脱敏=骨架通用化，具体单位与人名不入模板。

### 示例二 · 文件批量处理类

用户先为书 A 手工做了一次"下载→转码→分册→建索引"的语料整理，轮到书 B 时流程完全重复。

- **扫描**：场景重发✓（A、B 两书同流程）；步骤决策点✓（源格式判断→转换→切分→核验，每步有失败分支）；模板清单✓（转换脚本与核验清单已存在）→ **构成候选**；
- **提案要点**：候选名"批量入库工具"；把一次性脚本参数化（书名/章节数/输出目录），第二本起一行命令完成；选址=本地脚本够。

### 示例三 · 已固化护栏被排除（1.1.0 新增，演示第零筛）

用户反复问“装第三方技能前要不要审”，每次都要重讲一遍审计项。

- **第零筛**：审计项已写成纪律文件、且已有配套审计器在跑 → **护栏已固化，排除**，不提案；
- **换个角度才成立**：不重提“审什么”，而是提“装前决策树”（本地前提／联网范围／作者版本线），且必须写清与现成审计器的分工——**否则就是重造已固化的东西**。

### 反例（明确"不建议"）

用户让 AI 查了一次某政策文件的发布日期——无场景重发、无步骤决策点、无模板产出，三条全不中，直接回答"不建议"，一句话说明理由即可，不展开分析。

## 常见问答

- **"我什么都不会，能用吗？"**——能。你只负责两件事：回答"这类活以后还有没有"，以及对提案说"建"或"不建"。
- **"我提出的需求很冷门，值得吗？"**——够冷门反而是优势：通用技能市场已有人做，行业/岗位专属流程往往空白。提案里会注明预估受众。
- **"一次能提炼几个？"**——通常 0–2 个。产出很多候选反而说明判据没收紧（见偏差处置预案"判据放水"条）。
- **"会不会提我已经做过的技能？"**——不该发生。第 0 步动作 0-1 会先读历史提案的三张名单（已建／已否决／缓议），只提不在名单里的。若你发现我又提了一遍，直接说"查历史"，我撤回并记档。
- **"怎么算'重复出现'？"**——按**独立场合**算：不同日期、不同对象、不同目录各算一次；同一个目录里堆十个文件，仍然只算一次——那是"一次长往来"，不是十次需求。
- **"提案被否了怎么办？"**——正常流程，不是失败：否决意见本身就是校准，下次扫描判据会更准。被否的提案标注日期存档，不再重复提出。
- **"扫描完说没有候选，是不是白跑了？"**——不是。"本周无可孵化候选"是合格产出，说明判据在工作；不要为了"有产出"硬凑候选。
- **"想中途停下怎么办？"**——任意一步说停就停：第 2 步前停下=什么都没建，零残留；已建档的想撤销，删目录即回滚。

## 跨宿主说明（信息性）

- 兼容技能根目录：Claude Code（~/.claude/skills）、Codex（路径以其文档为准）、Copilot CLI（~/.copilot/skills 或 ~/.agents/skills）、OpenCode（~/.config/opencode/skills）、WorkBuddy（~/.workbuddy/skills）等，以实际宿主文档为准；
- 本技能只依赖"读取会话/笔记文本"与"写文件"两项基础能力，不要求 shell、网络或特定 MCP；纯文档实现，Windows/macOS/Linux 通用。
