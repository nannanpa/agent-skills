# 技能孵化器（skill-miner）

把"手艺人的隐性经验"显性化：用户在日常对话中积累的流程经验、公文套路、排查手法，大多随会话结束而流失。本技能负责**回看任务历史、发现可复用模式、产出候选提案**——它是 skill-creator 类技能的上游：先回答"什么值得建"，再交给"怎么建"。

**给非技术用户的承诺**：你不需要懂任何术语。一句话（如"帮我看看咱们的任务里能不能提炼 skill"）即可触发，全程只需做选择题。

## 使用时机

- 用户明确询问："我让你帮我完成的任务里，是否能够提炼一个或多个 skill？"
- 用户表达固化意愿："这个流程以后还要用""能不能把这套做法存下来"。
- 定期回顾（可选）：用户要求盘点近期能力产出时。

**不要主动滥用**：没有用户发起或明确要求时，本技能不自动运行——提炼是提案，不是打扫。

**触发说法示例**（下列说法出现即启动）：

- 「我让你帮我完成的任务里，能不能提炼一个或多个 skill？」
- 「帮我看看最近的工作里有什么值得做成技能的」
- 「这套做法以后还要用，能不能固化下来？」
- 「盘点一下近期能力产出」

**降级处理**：若本技能文件不可读或宿主未正确加载，用户可直接说"按 skill-miner 的六步流程手动走一遍"——AI 依据本 SKILL.md 的工作流照做即可，不依赖额外机制。

### 什么情况不用

- **一次性任务**：不会再发生的操作（装一次软件、查一次资料）不构成候选；
- **纯灵感无步骤**：没有操作顺序与决策点的点子，无法固化成流程；
- **已有现成技能**：目标宿主技能市场已有同类的，建议直接安装而非自建。

### 可选进阶 · 定期自动盘点（用户自建）

技能机制不含"装后自动运行"。若你希望定期盘点，请**自行创建**一个定时任务（自动化/计划任务），提示词参考：

> 调用 skill-miner，扫描最近一周的任务记录，若有满足判据的候选按一页纸提案输出；没有就说"本周无可孵化候选"，不做多余分析。

建议频率：**每周一次**足够（skill 从任务里长出来是周级节奏，天天扫只会产出空转报告和 token 账单）。随时可停，停了不丢任何东西——提案文件都在。

## 工作流程（第 0–5 步，共六步）

> 第 0 步含四个动作（0-1 查历史／0-2 读素材／0-3 数场合／0-4 断点续跑）；**"第 5 步"是 1.1.0 起新增的收尾自查**，不属于主干流程本身。

### 第 0 步 · 圈定素材

**动作 0-1 · 先读历史提案（防重复提案）**：打开 `<技能目录>/skills-candidates/`（**目录不存在就先创建**——只建提案目录，绝不建技能目录），把旧提案逐份读成三张名单——**①已建**（技能名＋日期）**②已否决**（日期＋理由）**③缓议**（观察判据＋到期日）。本轮只提不在这三张名单里的候选。名单字段不统一时按 `references/执行细则速查.md` §二 的字段归一规则处理；**状态识别不出的按"不可重提"处理**——宁可漏提，不可重提。

> 为什么放在最前面：提案消耗的是用户的注意力。不查重就提问，等于让用户替我做本该我做的查重——而且他会以为我忘了。

**动作 0-2 · 读素材**：回看**本会话上下文**与**可访问的任务记录/工作笔记/记忆文件**。只看近期的、实际发生过的任务——不推测、不虚构。不同来源该怎么读、怎么算一次场合、各宿主的素材入口在哪，见 `references/执行细则速查.md` §三/§四。

**动作 0-3 · 按"独立场合"数反复（防频次误判）**：数"这类需求发生过几次"，**不数文件数**。同一目录下堆十个同类文件＝**一次**长往来；跨日期、跨对象、跨目录各算一次。频次只看得见"写了多少"，看不见"发生在几次"。

**动作 0-4 · 断点续跑（防中断白跑）**：开扫前先把"本次已读素材清单"落到工作区（提案同目录下的 `本次素材清单.md`）；重跑时先读该清单，**已读过的直接跳过**，不从头再来。

**除成品任务外，优先检查同一件事被反复执行、试错、回退的段落**（1.0.4 补）。反复本身就是缺护栏的信号：护栏类小工具（校验脚本、批处理补丁、防呆检查单、错误处置规则）多埋在这些"折腾过程"里——很多技能正是从任务执行中的临时补丁长出来的。注意区分两种情况：护栏**已固化**（补丁已打进脚本/纪律已写成文件）＝已排除，不重复提案；护栏**只在对话里口头存在**＝优先提案对象。

### 第 1 步 · 复盘扫描（发现模式）

**第零筛（先筛再判，1.1.0 新增）**：命中"护栏已固化"的直接排除（补丁已打进脚本、纪律已写成文件、检查单已在跑）——固化＝问题已解决，重复提案只是重造。**过筛的才进三判据**。

在过筛的素材中，筛同时满足三条判据的模式：

1. **场景重发**——同一类需求在**两个以上独立场合**出现过（不同日期、不同对象或不同目录各算一个场合；**同一目录下十个文件仍只算一次场合**），或用户明言"以后还会这么干"；
2. **有步骤、有决策点**——存在可描述的操作顺序和判断分支，不是一次性灵感；
3. **有模板/清单/规则产出**——曾沉淀出可复用的表格、清单、文案骨架、检查规则。

三条全中才是候选；只中一两条，明确说"不建议"，并说明差在哪。

### 第 2 步 · 候选提案（只提案，不建）

每个候选输出**一页纸提案**，固定 **9 个字段**：

1. **状态**——待裁／已建（技能名＋日期）／已否决（日期＋理由）／缓议（观察判据＋到期日），四选一，必填；
2. **证据**——具体事项 1–3 条，标明是**几个独立场合**；
3. **解决什么**——一句话说清它替用户省掉哪一步重复劳动；
4. **覆盖范围**——核心场景 1 句 ＋ 边界外场景 1 句（诚实边界）；
5. **市场核查**——有→写明差异；无→写"未命中"；没查→写"未查"。**不许留空**；
6. **选址结论**——本地脚本够／需要外部连接／仅说明壳，并说为什么；
7. **敏感信息检查**——需脱敏的内容清单；确无时写"无（理由：…）"，**不许只写一个"无"字**；
8. **产物**——完整落点路径（含日期与主题名）；
9. **技能目录来源**——用户指定，还是探测第几条（见 `references/执行细则速查.md` §一）。

**模板、填写完成的样例、字段校验清单、反例对照**：`references/提案模板与样例.md`——**动手写提案前照它填**。

**校验规则**：产出前逐项核对 9 个字段；缺任一项用 `<待填>` 占位，并在文末列「待补字段」，**不许静默漏项**——漏项的提案看着完整，实际不可用。

**铁律：只提案，不直接建技能。** 提案权在本技能，批准权在用户——用户明确说"建"才进入第 3 步。一页纸都没有的候选不许口头带过。

### 第 3 步 · 批准后建档（先过选址阀，再落盘）

**选址阀（建之前必答）**：落盘前再答一遍——"本地脚本够不够？要不要外连？值不值套壳？"

- 答"本地脚本够" → 按下面的通用最小集建档；
- 答"需要外部连接"或"仅说明壳" → 先把理由说清，用户认可再建；
- 一次性任务不建；层放错＝维护翻倍。

**答完选址阀**，用户批准后，按目标宿主的技能规范建档（通用最小集）：

```
<skill-name>/
├── SKILL.md        # 必需：frontmatter（name/description）＋工作流
├── references/     # 可选：模板、清单、分册语料
├── scripts/        # 可选：可执行脚本（确有自动化价值才写）
└── LESSONS.md      # 复盘层：踩坑与口径修正——永不进发布版
```

- 若宿主已有 skill-creator 类技能，**交给它完成建档**，本技能只交付提案与骨架要点，不重复造轮子；
- **建档后必须回填索引（1.1.0 新增）**：在该宿主的沉淀索引（如总目录 INDEX、技能清单）里补一行——名称／路径／用途／何时用。**不登记等于没沉淀**：建了技能却查不到，下次扫描照样找不到，等于白建；
- SKILL.md 写法保持**宿主中立**：不写死任何一家的安装路径；需要提路径时按宿主各自约定注明；
- **`<技能目录>` 怎么落地**：用户未指定时按 `references/执行细则速查.md` §一 的顺序自动探测，并在产物里写明实际路径与来源（用户指定／探测第几条）；四条都没命中就如实说明并请用户指定，**不猜**。

### 第 4 步 · 脱敏闸（每次必过）

拟对外分享的版本，逐项 grep 人名、机构名、内部数据、密钥口令；"私用版"与"发布版"分目录；复盘层（LESSONS）永不进发布版。

> 1.2.1 调整：原第 4 步叫"双安全阀"，把选址阀与脱敏阀并列在建档之后，而选址阀自己写着"建之前再答一遍"——顺序与说法打架。现拆为两处：**选址阀在第 3 步落盘前**（建之前必答），**脱敏闸在第 4 步**（对外分享前必过），两闸各守其位。

### 第 5 步 · 收尾自查（1.1.0 新增，1.2.0 补断点续跑问：不留「待回流」）

每次运行结束前答四问，答完才收工：

1. **本次产生"待回流经验"了吗？**（发现流程漏洞、写法没规定、口径要改）→ 有则**当场改 SKILL.md 或写进 LESSONS.md**，标日期。**禁止只写“待回流”三个字就收起**——实证：一条"待回流"在文件里躺了九天没人动。
2. **提案的“状态”字段都填了吗？**（待裁／已建／已否决／缓议）没填的下次扫描无法判断该不该重提。
3. **本次提案里有没有真实人名、内部数据、本机绝对路径？**有则按脱敏闸清理后再交。
4. **本次扫描中断过吗？留了半成品提案吗？**有则**续写，不要重开**：读回第 0 步落的「本次素材清单」与已写草稿，从断点接着写；已读过的素材不重扫。

## 偏差处置预案

| 偏差症状 | 纠偏句式（对 agent 说） | 恢复动作 |
|---|---|---|
| 越权直建：没出提案就动手建了技能目录 | "退回去——先出一页纸提案，我批了再建" | 删除未批准的目录，回到第 2 步 |
| 判据放水：**最终提案数 > 2**（命中数不限，但每个命中都得写明“提／不提”与理由） | "判据收紧——三条全中的才算，逐一说明证据" | 逐候选复验三判据＋第零筛，砍到 0–2 个 |
| 无中生有：提案引用的任务在记录里查无实据 | "只看实际发生过的任务，虚构的剔除" | 重跑第 0 步圈定素材，只保留可引用条目 |
| 重复提案：提了一个已建过／已否决／正在缓议的技能 | "先查历史提案——三张名单里有它" | 回到动作 0-1 读旧提案，当轮撤回并记档 |
| 频次误判：把“一次密集往来”当成“长期高频”（例：同一目录十几封函） | "按独立场合数重算，不是数文件数" | 按日期×目录重新归并场合，再排优先级 |
| 过程废料当噪音：把"反复试错/回退"的段落跳过没读 | "折腾段落优先精读——反复=缺护栏的信号" | 回到第 0 步补扫过程段落；护栏已固化＝排除，未固化＝按三判据走提案 |
| 敏感夹带：提案里出现人名/机构/内部数据 | "脱敏后再给我——提案里只留职务与流程，不留具体的人和事" | 按脱敏闸逐项 grep 清理后重新提交 |
| 用户否决后反复推销 | "否了就是否了，记档不再提" | 提案文件标注"用户否决（日期）"，本轮不再复述 |

**技术面异常**：本技能为纯文档实现，无 try-catch。遇技术故障一律按**统一格式**输出：`[E1] 原因 → 我已做的 → 需要你做的`，不许只说"出错了"。错误码与逐条处置见 `references/执行细则速查.md` §五（含重试上限：同一文件失败重试 1 次即转降级动作，不循环重试）。

## 场景示例（三类＋一反例）

- **文档/材料写作类**——同类材料反复起草、每次都要"跟上次一样的格式"：场景重发✓＋步骤决策点✓＋模板清单✓ → **构成候选**；
- **文件批量处理类**——同一套流程在第二个、第三个对象上完全重复 → **构成候选**；
- **已固化护栏被排除**——护栏已写成纪律文件且有审计器在跑 → **第零筛排除，不提案**（换个角度才成立）；
- **反例**——只查过一次政策文件发布日期：三条判据全不中，回答"不建议"即可。

完整展开（扫描理由、提案要点、边界写法）与「这些一律不算候选」的情形清单，见 `references/场景示例.md`。

## 常见问答

- **"我什么都不会，能用吗？"**——能。你只负责两件事：回答"这类活以后还有没有"，以及对提案说"建"或"不建"。
- **"我提出的需求很冷门，值得吗？"**——够冷门反而是优势：通用技能市场已有人做，行业/岗位专属流程往往空白。提案里会注明预估受众。
- **"一次能提炼几个？"**——通常 0–2 个。产出很多候选反而说明判据没收紧（见偏差处置预案"判据放水"条）。
- **"会不会提我已经做过的技能？"**——不该发生。第 0 步动作 0-1 会先读历史提案的三张名单（已建／已否决／缓议），只提不在名单里的。若你发现我又提了一遍，直接说"查历史"，我撤回并记档。
- **"怎么算'重复出现'？"**——按**独立场合**算：不同日期、不同对象、不同目录各算一次；同一个目录里堆十个文件，仍然只算一次——那是"一次长往来"，不是十次需求。
- **"提案被否了怎么办？"**——正常流程，不是失败：否决意见本身就是校准，下次扫描判据会更准。被否的提案标注日期存档，不再重复提出。
- **"扫描完说没有候选，是不是白跑了？"**——不是。"本周无可孵化候选"是合格产出，说明判据在工作；不要为了"有产出"硬凑候选。
- **"想中途停下怎么办？"**——任意一步说停就停：第 2 步前停下=什么都没建，零残留；已建档的想撤销，删目录即回滚。
- **"references/ 里的文件要一起装吗？"**——要，放在 `skill-miner/references/` 下。**正文含全部主干流程**（六步流程、提案 9 字段、偏差处置表、统一错误格式 `[E1] 原因 → 我已做的 → 需要你做的`），但**错误码表 E1–E7 的逐条处置在 `references/执行细则速查.md` §五**，正文只留格式与指针。装上 `references/` 才能逐条查处置办法；**只装 SKILL.md 也能跑**，遇到技术故障时按正文给的统一格式降级输出即可。

## 跨宿主说明（信息性）

本技能零依赖、零网络、纯文档实现，只要求"读取会话/笔记文本"与"写文件"两项基础能力，不要求 shell、网络或特定 MCP；Windows/macOS/Linux 通用。按宿主能力分三类装法：

**第一类 · 目录型宿主**——把 `skill-miner/` 整个目录放进技能根目录即可：

| 宿主 | 技能根目录 |
|---|---|
| WorkBuddy | `~/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` |
| Copilot CLI / 其他兼容 agent | `~/.copilot/skills/`、`~/.agents/skills/` 或项目 `.agents/skills/` |
