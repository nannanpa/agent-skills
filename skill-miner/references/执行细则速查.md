# 执行细则速查（skill-miner 参考文件）

> 本文件是 SKILL.md 第 0 步的执行细则。**正文只给动作，细则在这里查**——查到哪条用哪条，不必通读。

---

## 一、技能目录默认解析规则（`<技能目录>` 占位符怎么落地）

正文与模板里的 `<技能目录>` 是占位符。**用户没有指定时，按下列顺序自动探测，并把最终采用的路径写进产物里**（不静默选一个让用户猜）：

| 顺序 | 探测路径 | 命中条件 |
|---|---|---|
| 1 | 当前工作区 `.workbuddy/skills/` | 工作区内有该目录，且其中含 `skills-candidates/` 或既有技能目录 |
| 2 | `~/.workbuddy/skills/` | 本机用户级技能根目录存在 |
| 3 | 宿主技能目录 | 按各宿主文档约定的技能根目录（Claude Code `~/.claude/skills/` 等） |
| 4 | 项目 `.agents/skills/` | 兼容多宿主的项目级技能目录 |

- 四条都没命中：**不猜**——把探测结果与失败原因告诉用户，请其指定一个路径，或直接在对话里交付提案全文（写入只是留档手段，不阻塞提案本身）；
- 用户指定的路径**优先于**以上探测顺序；
- 产物里必须写一行：`技能目录：<实际路径>（来源：用户指定 / 探测第 N 条）`。

## 二、提案目录与历史提案的处理

### 2.1 目录不存在 → 自动创建

`skills-candidates/` 不存在时**直接创建再读**。这不算越权：本技能只建自己的提案目录，**绝不建技能目录**（建技能目录必须经用户批准，走第 3 步）。

### 2.2 三张名单的字段统一规则

历史提案是过去不同时间、不同写法攒下的，格式不一定一致。统一成四个字段来读：

| 字段 | 取值 | 识别方式 |
|---|---|---|
| 技能名 | 提案标题里的技能名 | 标题含「候选技能：」或首行标题 |
| 日期 | `YYYY-MM-DD` | 文件名日期前缀优先，其次提案内标注的日期 |
| 状态 | 已建／已否决／缓议／待裁 | 优先读提案里的「状态」字段；无该字段时按关键词兜底 |
| 判据 | 已否决的理由／缓议的观察判据与到期日 | 同上，从状态字段或正文末段取 |

- 关键词兜底表：出现「已建/已发布/已上线」→ 已建；出现「否决/否了/不用做」→ 已否决；出现「缓议/再看看/观察」→ 缓议；出现「待裁/待定」→ 待裁；
- **识别不出状态的**：标记为「状态不明」，并按**不可重提**处理——宁可漏提，不可重提。写清理由："历史提案状态无法识别，按不可重提处理，需要时请人工确认"。

### 2.3 三张名单之外的候选照常提

不在名单里 ≠ 不能提；名单里的**一律不提**。

## 三、素材格式识别表

不同来源的素材，读法与计数口径不同。按下表处理：

| 素材来源 | 读什么 | 怎么算「一个独立场合」 | 常见坑 |
|---|---|---|---|
| 本会话上下文 | 本次对话里用户交代过的任务与实际产出 | 一次对话里的连续一件事＝一个场合 | 同一件事的追问与返工不另计 |
| 会话历史记录 | 宿主保存的历史会话文本 | 按**日期**切分：不同日期＝不同场合 | 同一天的多轮对话通常是一件事 |
| Markdown 笔记／工作日志 | 笔记正文、每日工作日志 | 按笔记标题的**事项**计，同一事项跨多日仍算一次 | 把日报当场合会虚高 |
| JSONL／机器日志 | 逐条记录 | 按记录里的**任务标识**去重 | 同一任务的多条状态更新不重复计 |
| 表格台账 | 每一行一条记录 | 按行的**日期列＋对象列**组合去重 | 同一天对多个对象分别做，算多个场合 |
| 交接／归档文件 | 交接正文、纪要 | 按文中的**事项段落**计 | 整篇交接稿通常含多件事，别当一场 |

**统一口径**：只有当两处素材**日期不同、或对象不同、或目录不同**时才拆成两个场合；同一批文件里的同一件事永远只算一次。

## 四、各宿主素材入口速查

宿主不同，任务记录落在哪儿也不同。**按实际宿主文档为准，以下是常见位置与通用兜底**：

| 宿主 | 任务/会话记录 | 笔记与索引 | 提案目录 |
|---|---|---|---|
| WorkBuddy | 会话历史；`.workbuddy/memory/` 下的工作日志与长期记忆 | 工作区笔记、记忆分册 | `<技能目录>/skills-candidates/` |
| Claude Code | 会话记录（`~/.claude/` 下） | `CLAUDE.md` 约定目录、用户笔记库 | 同上 |
| Copilot CLI / OpenCode / Codex 等 | 以其文档约定的会话与项目目录为准 | 同上 | 同上 |
| 通用兜底 | **当前工作目录**与用户当场粘贴的文本 | 当前工作目录内的索引文件 | 同上 |

**兜底顺序**：宿主专属位置 → 当前工作目录 → 用户粘贴。三处都没有素材，如实说明"本轮无可读素材"，不推测、不虚构（宁可交一份"无可孵化候选"，也不要编）。

## 五、技术面异常 · 错误码表

本技能为纯文档实现，无 try-catch。遇技术故障一律按**统一格式**输出：

`[E1] 原因 → 我已做的 → 需要你做的`

不许只说"出错了"，不许静默跳过素材。

| 码 | 症状 | 我已做的 | 需要你做的 | 阶段 |
|---|---|---|---|---|
| E1 | 路径不存在 | 说明原因并列出实际可用目录 | 给正确路径，或直接粘贴文本 | 读素材 |
| E2 | 权限不足 | 输出已读到的可读部分 | 授权后重试 | 读素材 |
| E3 | 编码错误 | 以 UTF-8 重试 1 次 | 无（仍失败即转 E6） | 读素材 |
| E4 | 写入失败 | 换临时文件重试 1 次；仍失败则把全文输出到对话 | 无（写入只是留档手段，不阻塞提案） | 建档 |
| E5 | 素材太多扫不完 | 按独立场合分批，不静默抽样假装全扫 | 圈定范围（时间窗／项目） | 读素材 |
| E6 | 素材格式无法解析 | 跳过并列入「未解析清单」 | 无（**不臆测其内容**） | 读素材 |
| E7 | 建档阶段失败 | 回滚半成品目录，报失败步骤与已有文件 | 确认后重试 | 建档 |

**重试上限 1 次**：同一文件读/写失败，重试一次即转对应降级动作，不循环重试。
